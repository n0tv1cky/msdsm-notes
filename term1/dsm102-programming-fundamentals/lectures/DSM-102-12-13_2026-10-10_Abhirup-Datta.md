### 2.5 Mean salary per rank (bar plot with error bars)

A count says nothing about *how much* each rank earns, so the mean was plotted instead:

```python
sns.barplot(x='rank', y='salary', data=df)            # error bars shown (default)
sns.barplot(x='rank', y='salary', data=df, ci=None)   # older syntax: no error bars
# newer Seaborn (>= 0.12): errorbar=None replaces ci=None
```

- Result: mean salary of **Prof > AssocProf > AsstProf**. A professor's mean is roughly 1,20,000.
- **What is `ci`?** It stands for confidence interval (95% by default). The instructor said the parameter is **deprecated** in newer Seaborn. In current versions the equivalent is `errorbar=None` or `errorbar=('ci', 95)`.
- **The "sticks" on the bars are error bars.** A student asked whether they are outliers. They are not: they show the uncertainty in the estimated mean.

**Correction to the sigma figures given in class.** The instructor said "3σ covers 68%, 5σ covers 97%" and that the default bar is about 3σ. These figures are not correct:
- For a normal distribution, the coverage is:
  - $\mu \pm 1\sigma \approx 68.3\%$
  - $\mu \pm 2\sigma \approx 95.4\%$
  - $\mu \pm 3\sigma \approx 99.7\%$
- Seaborn's default error bar is a **95% bootstrapped confidence interval of the mean**. It describes uncertainty in the mean, not the spread of individual salaries.

Use the standard values in exams.


- After `dropna()` there were still 16 columns but **157,927 rows**.
- Rows lost: $160{,}754 - 157{,}927 = 2{,}827$. The instructor rounded this to "about 2,000+".

**Should you always drop rows? (student question)** No. The choice is subjective and depends on the data.

- **The missing column is not important for your analysis:** you can keep the row.

### 2.13 Numerical integration with SciPy (second half)

**Why numerical methods are needed**
- Analytically, a variable such as $t$ in $\int_0^x f(t)\,dt$ can take any value in a continuous range.
- On a computer everything is **discrete**: a grid has finite spacing $\Delta x$.
- As $\Delta x \to 0$ you approach the continuum, but you never reach it.
- **Integration = area under the curve.** For example, $\int_4^{14} y\,dx$ is the area under $y(x)$ between $x=4$ and $x=14$.
- Documentation: run `scipy.integrate?` in Jupyter to open the manual page.

**Example 1**

The function, as spoken, was:
$$f(x) = \frac{1}{x^2} + 6\sin(x) + \sqrt{x}$$
This reading of the formula is inferred from "1 / x² + 6 sin fx plus root of x".

```python
import numpy as np
from scipy import integrate

def f(x):
    return 1/x**2 + 6*np.sin(x) + np.sqrt(x)

x = np.linspace(1, 15, 256)   # 256 points between 1 and 15 -> sets Δx
y = f(x)

plt.plot(x, y)
plt.fill_between(x, y, where=(x >= 4) & (x <= 14))   # shade area; exact code inferred
plt.show()

result, error = integrate.quad(f, 4, 14)   # returns (value, estimated absolute error)
print(result, error)
```

**Output and caveats**
- The value spoken was roughly "−28.2988". The digits are unclear from the audio.
- The returned error was near **floating-point precision**.
- *Caution:* for the function as reconstructed, the analytic value of $\int_4^{14} f(x)\,dx$ is about $+25.0$. Either the function or the reported number was mis-transcribed. Rerun this yourself.

**Changing the grid**
- The instructor raised the number of points from 256 to **2048** (`np.linspace(1, 15, 2048)`). The value changed only slightly and the error shrank slowly.
- *Note:* `quad` evaluates the function itself and does not use the `x` grid. A grid-dependent result implies the integration was done on sampled data (trapezoid or Simpson). Treat this part as uncertain.

**Example 2: Gaussian with noise**

The function was:
$$y = 2\,e^{-x^2/5} + \text{(small random noise)}$$
on $x \in [-2\pi, 2\pi]$ with `nmax = 128` points.

```python
nmax = 128
x = np.linspace(-2*np.pi, 2*np.pi, nmax)
y = 2*np.exp(-x**2/5) + 0.2*np.random.random(nmax)   # noise amplitude inferred (see below)

plt.plot(x, y); plt.show()

a1 = integrate.trapezoid(y, x)   # trapezoidal rule (older name: integrate.trapz)
a2 = integrate.simpson(y, x=x)   # Simpson's 1/3 rule (older name: integrate.simps)
print(a1, a2)                    # class got ~9.238 and ~9.182
```

- **Plausibility check on the noise amplitude:**
  - The noise-free area is $2\sqrt{5\pi}\,\mathrm{erf}(2\pi/\sqrt5) \approx 7.93$.
  - Noise with mean 0.1 adds about $0.1 \times 4\pi \approx 1.26$.
  - The total is about 9.2, which matches the class results. So a noise term like `0.2*np.random.random(nmax)` is consistent.
  - Your numbers will differ slightly because the noise is random.
- **Rename to remember:** `trapz` has become `trapezoid`. The old name is deprecated or removed in newer SciPy.
- **Methods mentioned:**
  - `quad` (adaptive quadrature on a function)
  - trapezoidal rule (on sampled data)
  - Simpson's 1/3 rule (on sampled data)
  - Different rules give slightly different answers.

**The rules on sampled points**

With $h = \Delta x$ and $y_i = f(x_i)$:

Trapezoidal rule:
$$\int_a^b f(x)\,dx \approx \frac{h}{2}\Big[y_0 + 2\sum_{i=1}^{n-1} y_i + y_n\Big]$$

Simpson's 1/3 rule ($n$ even):
$$\int_a^b f(x)\,dx \approx \frac{h}{3}\Big[y_0 + 4\sum_{i\ \text{odd}} y_i + 2\sum_{i\ \text{even},\,0<i<n} y_i + y_n\Big]$$

These formulas are standard background; they were not written out in class.

### 2.14 Linear algebra with SciPy

```python
from scipy import linalg

A = np.array([[1, 2], [3, 4]])
linalg.det(A)    # -2.0

B = np.array([[7, 9], [3, 8]])   # values unclear in audio ("7 9 3 3 8")
linalg.inv(B)    # matrix inverse
```

- **Worked determinant:**
$$\det\begin{pmatrix}1&2\\3&4\end{pmatrix} = (1)(4) - (2)(3) = 4 - 6 = -2$$
- **Why it matters:** curve fitting, regression and many numerical routines reduce to **matrix operations**. Solving linear equations amounts to matrix inversion, $A\mathbf{x}=\mathbf{b} \Rightarrow \mathbf{x} = A^{-1}\mathbf{b}$.
- SciPy is very powerful and worth knowing well.

### 2.15 Optimisation (conceptual)
- **Data science is not just machine learning.** You need statistics and linear algebra, and most of the work is **optimisation**.
- You maximise or minimise a **loss / penalty / target function**.
- **At an extremum:**
$$f'(x) = \frac{df}{dx} = 0$$
- **The second derivative classifies it:**
  - $f''(x) < 0$ gives a maximum.
  - $f''(x) > 0$ gives a minimum.

## 4. Syntax Rules, Common Mistakes and Tips

**Seaborn vs Matplotlib**
- Seaborn achieves in one line what takes several in Matplotlib.

**Deprecations to watch for**
- `ci=` in `sns.barplot` has been replaced by `errorbar=`.
- `integrate.trapz` has become `integrate.trapezoid`.
- `integrate.simps` has become `integrate.simpson`.
- If old code from the internet throws warnings or errors, check for renamed functions.

**Grouped data**
- `.count()` counts entries; it does not sum them.
- Check that group counts add up to the total number of rows (78 here).

**Error bars**
- Bar-plot error bars are confidence intervals on the mean, **not outliers**.

**Time columns stored as HHMM**
- Overnight flights wrap around 24 h. Add the date, or add 24 h, before computing durations.

**Missing values**
- Always check `info()` before and after `dropna()` to see how much data you lost (here 2,827 rows).
- Dropping is not always correct. Reconstruct a missing value from the other columns when possible.

**Large datasets**
- `sns.pairplot` on a big dataset is very slow. Consider selecting columns or sampling rows first.

**Numerical integration**
- A finer grid (larger `n` in `linspace`) brings results closer to the continuum, but improvement can be slow.
- `quad` takes a **function**. `trapezoid` and `simpson` take **sampled arrays**.
