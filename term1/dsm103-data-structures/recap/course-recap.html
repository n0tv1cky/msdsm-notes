Foundations and the 1-D array

The vocabulary, the address formula, and the first three array operations — all written with L and U, never a language's own indexing.

VOCABULARY

data vs information
34 is data; "age = 34" is information. A value only means something once it is tied to an attribute of an entity.
ADT
Logical description: a collection of data plus the operations on it, with no word about implementation. E.g. {5, 12, 16, 7, 10} with max().
data structure
The implementation of an ADT: its physical form, built from primitives (int float char double).

THREE WAYS TO CLASSIFY

linear | non-linear
array, linked list, stack, queue | tree, graph, heap, trie (jump through links; e.g. a family tree)
homogeneous | non-homogeneous
array: one type only | struct / record: name (string) + age (int) + salary (float). Types are laid out differently in memory: int 5 → 101 with a sign bit; float 5.5 = 55×10⁻¹ → sign | exponent | mantissa; char → an unsigned code. So a slot built for one type can't hold another. (Python's mixed lists hide this in library code.)
static | dynamic
array: fixed block L…U, contiguous; free space elsewhere is useless to it | linked list: grabs scattered free blocks and links them

1-D ARRAY FORMULAS

array
a finite, ordered collection of homogeneous elements in contiguous memory
size
$\text{Size} = U - L + 1$
address (mapping function)
$\text{Addr}(A[I]) = M + (I - L)\times W$
M = base address, W = bytes per element. Special case L = 1, W = 1: $M + (I-1)$.
I-th element
sits at index $L + I - 1$

THE THREE OPERATIONS (20 AUG) — state input, output, data structure first

  • Traverse — I ← L; while I ≤ U: process A[I]; I ← I+1. O(n) time, O(1) space.
  • Bubble sort — compare only neighbours, swap when out of order; each pass parks the largest at I, then I ← I−1. Inner loop is J < I, not ≤, or A[J+1] doesn't exist. O(n²) time, O(1) space. Flip the test for descending.
  • Linear search — FOUND flag + LOCATION (start at 0, or a negative number if 0 is a valid index). Loop ends for two reasons, so test FOUND after it. Best O(1), worst O(n).

LOOPS AND INDEXING

  • while / for check the condition first; do-while runs the body once before checking. With I = 5 and condition 5 < 4: while → 0 runs, do-while → 1 run.
  • 0-based: C, Python, Java. 1-based: R vectors, SQL SUBSTRING. So write algorithms with L/U and let the formula absorb the difference.
  • Selection sort (mentioned): compare one element with all the others. Bubble sort only ever compares adjacent pairs.

Why a data scientist needs this (S01):

  • Store, manipulate, answer queries fast: a self-driving car's decision that arrives after a minute is useless.
  • Stock ticker: the highest-value stock must already be sitting at the front. If you had to scan for it, another stock would have overtaken it by the time you got there. That's why heaps and priority structures exist.
  • Printer: 10 jobs come out in firing order (a queue). Add authority levels and the boss's job jumps ahead (a priority queue).
  • Follow / follower relationships are a graph. A TF-IDF matrix is symmetric, so storing both triangles is redundant (hence module 2).
  • "No single storage structure is good for all applications": judge every choice on time and space, and expect to trade one for the other.

2-D arrays and sparse (triangular, band) matrices

      
Memory is a single line, so a grid has to be flattened. Every formula here comes from one method: count what is stored before the element.

    


    

      

        
LOGICAL vs PHYSICAL

        

          
logical
$a_{ij}$ = row $i$, column $j$ of an $m\times n$ grid (two subscripts). 1-based throughout.

          
physical
contiguous 1-D memory → a mapping formula turns $(i,j)$ into one index

          
row-major
row 1, then row 2, … — the compiler default

          
column-major
column 1, then column 2, … — you write this conversion yourself

        

      

      

        
THE ONE METHOD

        
    
          
  • Find how many elements each row (or column) stores.
    • 
          
  • Add up the complete rows (or columns) before $a_{ij}$.
    • 
          
  • Add $a_{ij}$'s position inside its own row or column, counted from that row's first stored cell, not from column 1.
    • 
          
  • That sum is the index. Then $\text{Addr} = B + (\text{Index}-1)\,w$.
    • 
          
  • Costs one multiply plus some additions, so O(1) per access.
    • 
        

      

      

        
FULL m × n

        

          
row-major
$\text{Index} = (i-1)\,n + j$
$\text{Addr} = B + [(i-1)n + (j-1)]\,w$

          
column-major
$\text{Index} = (j-1)\,m + i$
$\text{Addr} = B + [(j-1)m + (i-1)]\,w$

          
index ≠ address
5 is a position. The address is $B + (5-1)w$. Class kept mixing these up.

Linked lists: singly and circular

      
Data goes wherever memory is free, and each node remembers where the next one is. Almost every bug comes from one of three things: where the pointer starts, which test ends the loop, or the order of two assignments.

    


    

      

        
NODE, HEADER, NULL

        

          
linked list
an ordered, finite collection of homogeneous nodes, whose linear order is kept by links

          
node
[data | link], where link = the address of the next node. Every node has the same fields.

          
header
same node type, data unused, link → first real node. It always exists, even when the list is empty.

          
NULL
the last node's link. It is the stop signal: without it you would read into memory you were never given.

          
no indexing
"node i" doesn't exist. You always walk from the header.

        

      

      

        
TWO REPRESENTATIONS

        

          
static
two parallel arrays of the same size: DATA[k] holds the value, LINK[k] holds the index of the next one. Fixed size.

          
dynamic
real pointers. getNode() returns a fresh node's address, or NULL when memory is full (overflow). With an 8 B int and an 8 B pointer, one node is 16 B.

          
ptr->data · ptr->link
the value · the address of the next node

          
GETNODE / RETURNNODE
take a block from the heap's free list / give it back. Memory is never "removed".

        

      

      

        
POINTER DISCIPLINE (the traps)

        
    
          
  • ptr = header + while ptr->link ≠ NULL stops on the last node and is safe on an empty list. Use it for insert at end, delete last, and concatenate.
    • 
          
  • ptr = header->link + while ptr ≠ NULL visits every node. Use it for traverse, search and copy.
    • 
          
  • Link the new node first, then redirect the old arrow, or you lose the rest of the list.
    • 
          
  • Deleting needs the predecessor, so use two pointers: ptr and ptr1.
    • 
          
  • A loop that can end for two reasons must be followed by a test that tells them apart: ptr->data = key.
    • 
          
  • Check getNode() = NULL before inserting, and check for an empty list before deleting.
    • 
        

      

    


    

      

        
SLL → CIRCULAR SLL (last node points back to the header)

        
    
          
  • Rule: every end-of-list NULL becomes header. So ptr ≠ header, ptr->link ≠ header, new->link ← header. Empty: header->link = header.
    • 
          
  • Insert at front: no change. It never looks for the end.
    • 
          
  • Insert at end: new->link ← header plus the loop test.
    • 
          
  • Insert after key: the mechanical conversion if ptr->link = header is wrong when the key is last. Test ptr->data ≠ key instead.
    • 
          
  • Delete first: only the underflow test changes. Delete last: three changes (underflow test, loop test, ptr1->link ← header). Delete key: two lines.
    • 
        

      

      

        
MORE OPERATIONS (S05)

        
    
          
  • Copy: a new header, then for each node getNode a fresh node, copy the data and hang it on ptr1. Two independent lists, with no arrow between them. O(n) time and O(n) space.
    • 
          
  • Concatenate: ptr = header1, walk to the last node, ptr->link = header2->link, then header2->link = NULL before RETURNNODE(header2).
    • 
          
  • Search: flag plus a location pointer. Loop while ptr ≠ NULL and flag = 0. The NULL test comes before any ptr->data, so empty lists and missing keys are safe.
    •

Doubly linked lists and sparse matrices as multi-linked lists

      
Adding a second link per node lets you walk backwards. Adding a header link to the last node turns "insert at end" from O(n) into O(1).

    


    

      

        
DOUBLY LINKED (DLL)

        

          
node
[LLINK | DATA | RLINK]: back to the previous node, forward to the next. The order you declare the fields in doesn't matter.

          
linear DLL
header LLINK = NULL · header RLINK → first node · last node's RLINK = NULL

          
traverse
one pointer: PTR = PTR->RLINK forwards, PTR = PTR->LLINK backwards. O(n).

          
insert at front
4 links: NEW→R, NEW→L, old first's LLINK, HEADER->RLINK. Fix the old first node's LLINK before overwriting HEADER->RLINK. O(1).

        

      

      

        
CIRCULAR DOUBLY LINKED (CDLL)

        

          
shape
last node's RLINK → header, and HEADER->LLINK → last node

          
payoff
insert at end: PTR = HEADER->LLINK reaches the last node with no walk. O(n) becomes O(1).

          
loop test
PTR ≠ HEADER instead of PTR ≠ NULL

          
empty-list trap
on an empty list PTR = HEADER->RLINK = NULL, and PTR->LLINK = NEW then crashes. Give the empty case its own branch.

        

        
DLL delete, search and insert at an arbitrary position were set as self-study. They use the SLL logic plus the left links.

      

      

        
SPARSE MATRIX, MULTI-LINKED

        

          
node (5 fields)
[i | j | DATA | ROW LINK | COL LINK]: row link → next non-zero in the same row, col link → next non-zero in the same column

          
row / column headers
same structure. A zero in i or j marks a header. A row header's DATA holds that row's count of non-zeros. Its ROW LINK → the row's first element, its COL LINK → the next row header.

          
main header
stores the number of rows and columns. Its links point to RH₁ and CH₁.

          
cost
reaching $(i,j)$ means walking at most $n + n$ steps, so O(n), against O(1) for an array. Avoids the O(n²) full scan.

    •

    • 
        
  • Free-space management: the OS chains its scattered free blocks into a linked list.
    •

Stacks and arithmetic expressions

      
A stack is an array or a linked list with one rule added: insert and delete at one end only. That rule is enough to reverse strings and evaluate expressions.

    


    

      

        
DEFINE ANY DATA STRUCTURE BY…

        
    
          
  • what data is stored (int, char, text…)
    • 
          
  • how it is arranged: linear (before/after) or non-linear (parent/child)
    • 
          
  • how it may be changed: insert, delete, update. This third rule is what makes a stack a stack rather than just an array.
    • 
        

        

          
stack
an ordered collection of homogeneous elements with insertion and deletion at one end only. LIFO: last in, first out.

        

      

      

        
ARRAY STACK (S08: 0-based, top = −1)

        

          
push(x)

pop()

it's an impossible index, and −1 + 1 = 0, so the first push needs no special case

Queues: linear, circular, linked

      
A queue uses two ends, each with one job: insert at the rear, delete at the front. The naive array version wastes the cells it has already served. Treating the array as a ring fixes that with pointer arithmetic alone.

    


    

      

        
QUEUE BASICS

        

          
queue
linear. Add at the rear (ENQUEUE, which takes a value), remove from the front (DEQUEUE, which takes none). FIFO: first in, first out. A stack is LIFO.

          
no update
you can't reach into the middle and change a value

          
growing restriction
array / list (insert or delete anywhere), then stack (one end), then queue (two ends, one job each)

          
pointers
stack: TOP · queue: FRONT and REAR, because the two jobs happen at different ends

        

      

      

        
ARRAY QUEUE Q[1…N] (S09)

        

          
empty
FRONT = REAR = 0. 0 is an impossible index, the same idea as the stack's −1.

          
one element · count
FRONT = REAR · REAR − FRONT + 1 (e.g. 5…10 holds 6). Linear only.

          
full
naive: REAR = N. True: FRONT = 1 AND REAR = N, which only makes sense with compaction.

          
two special cases (the exam trap)
enqueue into an empty queue also sets FRONT = 1. Dequeuing the last element (FRONT = REAR) resets both to 0.

        

      

      

        
CIRCULAR QUEUE (S10)

        

          
advance
$r = (r \bmod n) + 1$, $\;f = (f \bmod n) + 1$. When $r = n$ it gives 1; otherwise it is just $r+1$.

          
full
$(\text{rear} \bmod n) + 1 = \text{front}$: the rear sits right behind the front

          
empty
front = rear = 0. Deleting when front = rear resets both.

          
what changes
rear can be less than front, so $\text{R} - \text{F} + 1$ breaks. The capacity is still $n$: circularity adds utilisation, not space. Enqueue and dequeue are O(1).

        

      

    


    

      

        
THREE FIXES FOR THE FALSE "FULL"

        
    
          
  • 1 · Compact on full: when REAR = N but FRONT > 1, shift everything back to start at index 1, set REAR ← REAR − FRONT + 1 and FRONT ← 1, then insert. That costs O(N) whenever it happens.
    • 
          
  • 2 · Shift on every dequeue: FRONT stays at 1, so REAR = N becomes a true fullness test. Every dequeue costs O(N).
    • 
          
  • 3 · Circular: no shifting at all, so O(1). "We are just utilizing the space which is free. We are not doing anything extra to make the space free."
    • 
        

      

      

        
LINKED-LIST QUEUE

        
    
          
  • Enqueue (at the rear): new->link = NULL. If front = NULL, then front = rear = new and qhead->link = front. Otherwise rear->link = new; rear = new.
    • 
          
  • Dequeue (at the front): item = front->data; ptr = front->link; qhead->link = ptr; front = ptr. If front = NULL, also set rear = NULL.
    • 
          
  • No circular version is needed: nodes exist only for real items, so there are never idle slots. Both operations are O(1).
    •

Algorithms and Big-O

      
Count steps, not seconds. Then keep only how the count grows, because constants and small inputs don't matter.

    


    

      

        
ALGORITHM

        

          
definition
a sequence of unambiguous instructions that solves a problem, giving the required output for every legitimate input in finite time

          
vs program
an algorithm is language-independent (pseudocode). A program is one implementation of it in C, Pascal, and so on. One algorithm can have many programs.

          
five characteristics
uniqueness (each step has one meaning) · finiteness (it must stop) · precision · input/output (0 or more in, at least 1 out) · generality (works for every valid input)

        

      

      

        
MEASURING

        

          
why not seconds
5 s vs 10 s says nothing, because the CPU, disk, instruction set and compiler all differ. Count elementary steps, assuming each takes the same constant time.

          
T(n)
steps as a function of input size n. Time complexity and space complexity (memory) together make up computational complexity.

          
asymptotic
behaviour as $n \to \infty$. Adding 5 numbers costs nothing, but adding a million numbers matters.

        

      

      

        
BIG-O

        

          
definition
$f(n) = O(g(n))$ if there exist $c > 0$ and $n_0$ with $f(n) \le c\,g(n)$ for all $n \ge n_0$

          
meaning
an upper bound, up to a constant. Where the curves cross for small $n$ doesn't matter. Ω and Θ were named but not defined yet.

          
rule of thumb
keep the highest-order term and drop the constants: $2n^2+3n+5 \to O(n^2)$, $2n+c \to O(n)$, $3n\log n + 5n + 20 \to O(n\log n)$

        

      

    


    

      

        
ordernameexample from the course

Trees: vocabulary, binary-tree types and properties

      
The first non-linear structure: the course's level and height conventions, the three binary-tree shapes, and six properties with their derivations.

    


    

      

        
LINEAR → NON-LINEAR

        

          
linear
Array, linked list, stack, queue: data in a sequence, accessed one after another.

          
linked-list caveat
The nodes are not contiguous, but access is still sequential: you follow node after node.

          
tree
Hierarchical: you go left or right as the logic needs. Not contiguous either.

          
binary node
Three fields: data + left + right.

          
entry point
A tree algorithm is handed only the root. Every other node is reached from it.

        

      

      

        
DEFINITIONS (RECURSIVE)

        

          
tree
A finite set of ≥ 1 nodes: one designated root. The rest is split into $n \ge 0$ disjoint sets $T_1,\dots,T_n$, and each one is itself a tree.

          
string form
$\text{root}(T_1,\dots,T_n)$, then expand each subtree. A leaf is just its label.

          
binary tree
Either empty, or a root + two disjoint binary trees (left $T_1$, right $T_2$). Only this definition allows an empty tree.

          
n-ary
Decided by the maximum possible number of children, so a one-node binary tree is still binary. Degree = arity = that maximum.

          
course convention
Root at level 0; the child of a level-$L$ node is at $L+1$. $h$ = number of nodes on the longest root-to-leaf path = max level + 1. Other textbooks differ: use this one.

        

      

      

        
THREE BINARY-TREE SHAPES

        

          
complete
Every level holds its maximum ($2^L$). If even one node is missing, the tree is not complete.

          
almost complete
Every level except the last is full, and the last level is filled left to right. A gap on the left makes it just a binary tree.

          
strictly binary
Every node has 0 or 2 children, never 1. Leaves can sit at any level.

          
independent tests
With 13, 14, 15 missing the tree is almost complete but not strictly binary, because node 6 keeps one child. The reverse case also exists.

Representing and traversing binary trees

      
Store a binary tree in level-wise array slots or in LC | DATA | RC nodes, walk it in pre-, in- and post-order, and rebuild it from the in-order plus one other order.

    


    

      

        
ARRAY REPRESENTATION (LEVEL-WISE)

        

          
layout
Root first, then each level from left to right. A child or parent is found by arithmetic: O(1).

          
1-based (lecture)
LC $2i$ · RC $2i+1$ · parent $\lfloor i/2 \rfloor$ (integer division: 5/2 → 2)

          
0-based (supplementary)
LC $2i+1$ · RC $2i+2$ · parent $\lfloor (i-1)/2 \rfloor$. The rules change with the start index.

          
array size
$2^h - 1$ for $h$ levels. You reserve room for a full tree of that height, whether or not the nodes exist.

          
when it fits
Complete or almost complete trees. A skewed tree wastes most of the slots (see the table below).

        

      

      

        
LINKED REPRESENTATION

        

          
node
LC | DATA | RC: left-child pointer, value, right-child pointer. A leaf has both pointers NULL.

          
struct
struct Node { struct Node *LC; int data; struct Node *RC; };

          
not a linked list
It is a node structure with two pointers, not a chain.

          
space
Nodes are created only as needed, so there are no blank slots. This is the space-efficient representation.

        

      

      

        
THE SIX ORDERS

        

          
pre-order
$R,\ T_L,\ T_R$

          
in-order
$T_L,\ R,\ T_R$

          
post-order
$T_L,\ T_R,\ R$

          
the other three
$T_R,T_L,R$ · $T_R,R,T_L$ · $R,T_R,T_L$ are exact reverses of pre-, in- and post-order, so the course drops them.

          
recursive definition
A tree is a root plus a left subtree plus a right subtree. Apply the same order inside every subtree, down to the leaves.

        

      

    


    

      

        
TRAVERSAL ALGORITHMS AND COST

        
    
          
  • All three procedures start with if T = NULL: return. They then run visit, the LC call and the RC call in the order's sequence. Only the position of visit moves.
    • 
          
  • Time O(n), because every node is visited once. Space O(h) for the recursion stack (a stack, module 5), which becomes O(n) for a skewed tree. supplementary
    • 
          
  • By hand: go left to a leaf, finish that whole left subtree, then continue as the order says. Apply the rule inside every subtree.
    • 
          
  • Expression tree: operators at internal nodes, operands at the leaves. in → infix · pre → prefix · post → postfix
    •

  • Root = the first element of the pre-order, or the last element of the post-order.
    • 
          
  • In-order gives the split. Everything left of the root goes to $T_L$, everything right of it goes to $T_R$. Take the matching blocks of the pre- or post-order and recurse. A one-element block is a leaf.
    • 
          
  • Valid pairs: pre + in and post + in. Pre + post is not enough, because neither shows where $T_L$ ends.
    • 
          
  • Expression trees are strictly binary: each binary operator has exactly two operands. They can be complete or almost complete, but not always. Example: an operator root with + (P, Q) on the left and D on the right is almost complete and strictly binary, but not complete.

Binary search trees

      
A BST is a binary tree with an order rule at every node, so search, insert and delete each walk a single root-to-NULL path and cost $O(h)$: fast when the tree is bushy, no better than a list when it is skewed.

    


    

      

        
THE STRUCTURE

        

          
left subtree < node < right subtree
Must hold at every node, recursively, not only at the root. The root is just a parent that has no parent.

          
in-order = ascending
The in-order traversal of any BST is sorted. Pre-order and post-order show no order. Every insert and delete must keep the in-order sorted.

          
duplicates
< else right: an equal key goes right. <=: it goes left. BSTs normally reject duplicates, because with two 28s you cannot say which one to delete.

          
sorted input → skewed
Ascending input gives a right-skewed tree, descending gives left-skewed, random order gives a roughly balanced tree.

          
rebuild from one traversal
A general binary tree needs two traversals to rebuild. For a BST, sort the pre-order (or post-order) to get the in-order, and you have the two you need.

        

      

      

        
SEARCH AND INSERT

        

          
SEARCH-BST (iterative)
ptr ← root, flag ← FALSE. If equal, set flag TRUE. If less, go left. If greater, go right. The loop exits for one of two reasons: found (flag) or ptr = NULL (absent). Uses $O(1)$ extra space.

          
INSERT-BST
Run the same search down to the NULL slot, tracking parent, then set parent.left or parent.right ← newNode. The slide version stops when key = ptr.data (the duplicate check).

          
cost $O(h)$
Complete or balanced tree: $h = O(\log n)$. Skewed tree: $h = O(n)$. Insert and delete walk down the same way, so they are $O(h)$ too. Big-O rules are in m7.

        

      

      

        
DELETE: THREE CASES

        

          
Case 1 · leaf
Set the parent's pointer to NULL. Delete 27: 24.right ← NULL.

          
Case 2 · one child
Point the parent straight at the only child. Delete 45: 35.right ← 42. Delete 24: 29.left ← 27.

          
Case 3 · two children
Copy the in-order successor (or predecessor) into the node, then delete that node. Its removal is always Case 1 or Case 2.

          
successor | predecessor
Successor = leftmost node of the right subtree (has no left child). Predecessor = rightmost node of the left subtree (has no right child). For 29: successor 33, predecessor 27. For 20: successor 24, predecessor 16. For 35: predecessor 33.

          
parent pointer
You unlink a node by changing its parent's left or right pointer, so DELETE-BST carries parent, and sParent for the successor.

        

      

    


    

      

        
BINARY SEARCH TREE ≠ BINARY SEARCH ALGORITHM

        
    
          
  • BST: a tree that satisfies the property. You search it by walking down the tree.
    • 
          
  • Binary search: works on a sorted array (ascending or descending). Compare with the middle element, keep only one half, repeat. $\text{mid} = \left\lfloor \frac{\text{low}+\text{high}}{2} \right\rfloor$, time $O(\log n)$.
    • 
          
  • Linear search for comparison: 27 in 20, 25, 27, 30, 40, 50 is found after 3 comparisons (20, 25, 27). That is $O(n)$.
    •

    mid <- (low + high) / 2   // integer division
    if A[mid] == key: return mid

Heap trees, heap sort and threaded binary trees

      
A heap keeps the max (or min) at the root of an almost-complete tree stored gap-free in an array. Threads reuse a linked tree's $n+1$ null links so an in-order walk needs no stack.

    


    

      

        
WHY A HEAP · TWO PROPERTIES

        

          
why not a BST
Search is $O(h)$, but sorted input skews the tree and search drops to $O(n)$. A BST also has no notion of priority.

          
1 · order property
Max-heap: parent ≥ children, so the root holds the max. Min-heap: parent ≤ children, so the root holds the min. No sibling order: in the min-heap 15 → (45, 25), swapping 45 and 25 is fine.

          
2 · shape property
The tree is complete or almost complete: the last level fills from the left, with no gaps. A 15 hung where its left sibling is missing breaks this, so that tree is not a heap even if the order is right.

          
purpose
The max (or min) is always at the root, ready to take.

        

      

      

        
ARRAY REPRESENTATION

        

          
why an array
The shape property means no gaps: 95 85 45 75 25 35 15 55 65 fills slots 1–9. Trees that aren't complete are better stored linked.

          
1-based (used in class)
$$\text{left}=2i,\ \ \text{right}=2i+1,\ \ \text{parent}=\lfloor i/2\rfloor$$Left children sit at even indices. Example: $\text{parent}(5)=\lfloor 2.5\rfloor = 2$.

          
0-based
$\text{left}=2i+1$, $\text{right}=2i+2$, $\text{parent}=\lfloor (i-1)/2\rfloor$. The last formula holds only for 0-based arrays.

          
height (course convention)
$h$ = number of nodes on the longest root-to-leaf path. For 9 nodes, $h=\lceil\log_2 10\rceil = 4$.

        

      

      

        
OPERATIONS AND COST

        

          
INSERT · sift up
Put the key in the next free slot. Swap it with its parent while it is bigger; this may stop early. At most $h$ swaps, so $O(h)=O(\log n)$ time and $O(1)$ extra space.

          
DELETE · sift down
Only the root can be deleted. Removing it is $O(1)$. Move the last element to the root, then swap it with the larger child until both children are smaller. Restoring costs $O(\log n)$.

          
HEAPSORT
Swap the root with the last active element, shrink the heap by 1, sift down. That is $n-1$ deletions, so $O(n\log n)$, in place. A max-heap gives ascending order. Like bubble sort's passes (m1), the max parks at the end, but each pass costs $O(\log n)$ instead of $O(n)$.

          
building the heap first
The lecture started from a ready heap. A random array must be built into a heap first: $O(n\log n)$ by inserts, or $O(n)$ bottom-up (beyond the lecture). Heap sort stays $O(n\log n)$.

        

      

    


    

      

        
THREADED BINARY TREE

        
    
          
  • $n$ nodes have $2n$ link fields. Only $n-1$ are used (one per non-root node), so $2n-(n-1)=n+1$ are null. Example: 3 nodes → 4 null links.
    • 
          
  • A null left link points to the in-order predecessor. A null right link points to the in-order successor. These are threads.
    • 
          
  • Node layout: LTag | LC | Data | RC | RTag. Tag 1 = thread, tag 0 = real child. That costs only 2 extra bits per node.
    • 
          
  • The first node's left link and the last node's right link have no target, so they point to a dummy / header node.
    •

Graphs: representation, families, DFS and BFS

      
A graph is two sets, $G = (V, E)$. This module covers storing one (adjacency list, adjacency matrix, incidence matrix) so that degrees and edge counts can be read off, and walking one with a stack (DFS) or a queue (BFS).

    


    

      

        
DEFINITION AND TERMS

        

          
G = (V, E)
$V$ must be non-empty. $E$ may be empty: three isolated dots with $E = \emptyset$ is a graph. Every edge has two endpoints.

          
undirected | directed
$DB$ is the same edge as $BD$ | $(A, B)$ is an arrow $A \to B$. Going $B \to A$ needs its own edge (one-way roads, "follows").

          
simple
Two distinct endpoints per edge, no parallel edges, no loops.

          
multigraph
Parallel edges allowed. If $m$ edges join $u, v$, then $\{u, v\}$ has multiplicity $m$. No loops (class definition).

          
loop | pseudograph
A loop is an edge from B back to B | a pseudograph allows both parallel edges and loops.

          
N(v), deg(v)
$N(v)$ = the neighbours of $v$. $\deg(v)$ = the number of incident edges. In a digraph: in-degree $\deg^-(v)$, out-degree $\deg^+(v)$ (minus = in, plus = out).

        

      

      

        
THREE REPRESENTATIONS

        

          
adjacency list
Each vertex heads a linked list of its neighbours (or use a 2-column table). Order inside a list says nothing about edges among those nodes. Lists are symmetric if the graph is undirected. Presented as a poor fit for multiple edges, because the same neighbour would be listed twice.

          
adjacency matrix
$n \times n$, with $M[i][j] = 1$ if there is an edge $i$–$j$.
            
    
              
  • Undirected → symmetric ($M = M^T$), so store one triangle.
    • 
              
  • Directed → store the full matrix.
    • 
              
  • Multigraph → each cell holds the multiplicity (3 parallel A–B edges → $M[A][B] = 3$). A loop puts a nonzero value on the diagonal (the lecture used 1).
    • 
            

          
incidence matrix
Rows are vertices, columns are edges. A cell is 1 if the edge touches the vertex. Each column has two 1s, and a row sum is that vertex's degree. You can read which edge joins which vertices; an adjacency matrix has no edge identities.

        

      

      

        
SPECIAL FAMILIES

        

          
$K_n$ complete
Every pair of vertices is joined. $K_1$ is a dot, $K_2$ is one edge, $K_3$ is a triangle. Edges: $\frac{n(n-1)}{2}$ (standard, not stated in class), so $K_3$ has 3.

          
$C_n$ cycle
Edges $v_1v_2, \dots, v_{n-1}v_n, v_nv_1$. Requires $n \ge 3$.

          
$Q_n$ hypercube
$2^n$ vertices with $n$-bit labels. Two vertices are adjacent iff their labels differ in exactly one bit. $Q_3$ is a cube with 8 vertices; $000$ is adjacent to $001$, $010$ and $100$.

          
bipartite
$V$ splits into disjoint $V_1$ and $V_2$, and every edge crosses between them; no edge stays inside either set. Class example (the first attempt failed): $V_1 = \{A, B, D\}$, $V_2 = \{C, E, F, G\}$.

        

      

    


    

      

        
DFS vs BFS: SAME LOOP, DIFFERENT CONTAINER

        

          
DFS = stack (see m5)
Go as deep as possible; when stuck, backtrack. Loop: pop; skip the vertex if already visited; otherwise visit it and push its unvisited neighbours.

          
BFS = queue (see m6)
Visit the nearest vertices first, level by level. Enqueue at the rear, dequeue from the front. Same loop as DFS.

          
not unique
The order depends on the order in which neighbours are pushed or enqueued, so state your convention.

          
cost (reference, not stated in S16; see m7)
$O(|V| + |E|)$ with a list, $O(|V|^2)$ with a matrix. $O(|V|)$ extra space for the container and the visited set.

        

      

      

        
COUNTING EDGES (IN-CLASS Q&A)

        

          
undirected adjacency matrix
$|E| = \tfrac12\sum_i\sum_j M[i][j]$. Each edge is stored twice, at $(i,j)$ and at $(j,i)$.

          
directed adjacency matrix
$|E| = \sum_i\sum_j M[i][j]$. Each edge is stored once.

          
incidence matrix
$|E| = \tfrac12\sum_v\sum_e M[v][e]$, which is simply the number of columns.

          
deferred
The slides' "second theorem" (likely handshaking, $\sum \deg(v) = 2|E|$) was not covered. MST (Prim, Kruskal) and shortest paths (Dijkstra, Floyd–Warshall) are taught in the Algorithms course.

Sorting I: improved bubble sort, selection sort, in-place

      
Bubble-sort passes are covered in m1. This module adds the swapped flag, selection sort, the in-place idea, and the statement counts that decide which of the two to use.

    


    

      

        
SORTING, CLASSES, IN-PLACE

        

          
sorting
Arrange the elements of an array or list in ascending or descending order. In: an unordered sequence. Out: the same numbers, rearranged.

          
comparison-based
Order is decided by comparing elements: bubble, selection, insertion, quick, merge, heap, shellreconstructed. Both algorithms here are this kind.

          
non-comparison
No pairwise comparisons: bucket, counting, radixreconstructed.

          
in-place
Sorts inside the original array with constant auxiliary space, independent of $n$. 2, 10, 20 or even 100 variables are still constant. Auxiliary space $\propto n$ means not in-place.

          
swap via temp
temp = a; a = b; b = temp. The temp counts as auxiliary space, but it is constant. Both bubble and selection sort are in-place.

        

      

      

        
IMPROVED BUBBLE SORT (passes: m1)

        

          
one-pass guarantee
The largest value reaches the last position. The smallest is not guaranteed to reach the front. $n$ elements need $n-1$ passes.

          
version 1 · 0-indexed
i = 0 … n−2 (passes); j = 0 … n−i−2, so the last pair compared is list[n−i−2], list[n−i−1].

          
version 2 · 1-indexed
i = 1 … n−1; j = 1 … n−i, which skips the sorted tail. If a whole pass makes no swap, then swapped == false and the loop breaks. With 10 elements there are normally 9 passes; no swap at i = 5 stops it there.

          
T(n)
$\sum_{i=1}^{n-1}[3(n-i)+2] = 1.5n^2+0.5n-2 = O(n^2)$. That is 3 per inner iteration (compare, swap, set flag) plus 2 per pass (reset, check). Highest power wins (m7).

          
best · worst · average
Sorted input: one pass, $3n-3 = O(n)$ · smallest value at the end (it moves 1 step per pass): $O(n^2)$ · random: $O(n^2)$ (not derived)

        

      

      

        
SELECTION SORT

        

          
sorted | unsorted
The sorted part on the left starts empty. Each pass finds the minimum of the unsorted part and swaps it with the unsorted part's first element. i = the position being filled.

          
min holds an INDEX
min = i; for j = i+1 … n: if list[j] < list[min] then min = j.

          
if min != i
Swap only when it is needed, so there is at most one swap per pass and at most $n-1$ in total.

          
inner iterations
$n-(i+1)+1 = n-i$. Check: j = 2 … 10 gives $10-2+1 = 9$.

          
T(n)
$\sum_{i=1}^{n-1}[2(n-i)+2] = n^2+n-2$. Counting the swap as 3 statements gives $n^2+3n-4$. Still $O(n^2)$: constants don't matter.

          
best case O(n²)
There is no sortedness check, so sorted input still runs every comparison. Worst (reverse order) and average are also $O(n^2)$.

Merge sort, stability and recurrences

      
This module covers the ways a sort is classified (internal or external, in-place, stable), how merge sort uses divide and conquer with a linear-time merge, and how the recurrence $T(n) = 2T(n/2) + O(n)$ solves to $O(n \log n)$.

    


    

      

        
WHAT A SORT PROMISES

        

          
output
A permutation $a'_1, \ldots, a'_n$ of the input with $a'_1 \le a'_2 \le \cdots \le a'_n$. Descending order is also fine. Example: 8, 2, 4, 9, 3, 6 → 2, 3, 4, 6, 8, 9.

          
internal | external
internal: all the data sits in RAM while sorting | external: part of it stays on a slower device (disk)

          
in-place
Needs only $O(1)$ extra space. If the extra space grows with n, e.g. $O(n)$, the sort is not in-place. Bubble and selection sort are in-place; merge sort is not.

          
stable
Equal keys keep their input order. Example: 2, 5, 8, 5, 3 → 2, 3, 5, 5, 8, where the first 5 out must be the first 5 in. You only see the difference when keys carry records.

        

      

      

        
DIVIDE → CONQUER → COMBINE

        

          
divide
Split the problem into 2 or more sub-problems, level after level, until each is easy.

          
conquer
Solve the smallest pieces directly. One element is already sorted.

          
combine
Merge sub-solutions upward, level by level, until you reach the original problem.

          
problem tree
$P \to P_1, P_2 \to P_{11}, P_{12}, P_{21}, P_{22}$. Solve the leaves to get $S_{11}, S_{12}, S_{21}, S_{22}$. Then $S_{11}+S_{12} \to S_1$, $S_{21}+S_{22} \to S_2$, and $S_1+S_2 \to S$.

          
recursion
A method that calls itself, each time on a different range of the same array. That is why the call carries p, r as well as A. Example: A[1..8] → A[1..4], A[5..8].

        

      

      

        
MERGE SORT FORMULAS

        

          
MERGE-SORT(A, p, r)
if p < r: $q = \lfloor (p+r)/2 \rfloor$; sort A[p..q]; sort A[q+1..r]; MERGE(A, p, q, r). Initial call: (A, 1, n).

          
count x..y
$y - x + 1$ elements. Example: 1..6 → 6.

          
run sizes
$n_1 = q - p + 1$, $n_2 = r - (q+1) + 1 = r - q$

          
MERGE cost
$O(N)$ time. $O(n)$ extra space for L and R, so merge sort is not in-place.

          
recurrence
$T(n) = 2T(n/2) + O(n)$, $T(1) = a$ → $O(n \log n)$

        

      

    


    

      

        
MERGE(A, p, q, r) — HOW IT RUNS

        
    
          
  • Copy the sorted runs: A[p..q] → L[1..n1] and A[q+1..r] → R[1..n2].
    • 
          
  • i and j point at the current fronts (smallest remaining) of L and R.
    • 
          
  • For k = p..r: write the smaller front to A[k], then advance only the pointer it came from.
    • 
          
  • Use L[i] ≤ R[j]. On a tie the left (earlier) element goes first, which is what makes merge sort stable. The lecturer said "<"; with <, an equal key from R overtakes.
    • 
          
  • Leftovers (the lecture skipped this): when one side runs out, copy the rest of the other, or end L and R with an ∞ sentinel (the textbook trick).
    • 
        

      

      

        
SUBSTITUTION, IN FIVE MOVES

        
    
          
  • Assume $n = 2^k$ and write $O(n)$ as $cn + c_0$.
    • 
          
  • Plug in $T(n/2) = 2T(n/2^2) + c\frac{n}{2} + c_0$ → $2^2T(n/2^2) + 2cn + (c_0 + 2c_0)$.
    • 
          
  • After k steps: $2^kT(n/2^k) + kcn + (2^k - 1)c_0$.
    • 
          
  • $2^k = n$ gives $k = \log_2 n$: $an + cn\log_2 n + (n-1)c_0$.
    • 
          
  • Keep the dominant term (Big-O rules, m7): $O(n \log n)$.

Why stability and cheap merging matter (S19):

      
    
        
  • Student records A 80, B 70, C 80, D 60 (names partly reconstructed). A stable sort by marks keeps A's 80 ahead of C's 80, because A came first. An unstable one could "unfairly push back someone who was ahead". With plain numbers you can't see the difference.
    • 
        
  • Why a merge is cheap: both lists are already sorted, so the next output has to be one of the two fronts. Nothing else can be smaller. That means one comparison per output element, giving $O(m + n)$. Unsorted lists would need many comparisons per element (like bubble sort's n − 1 per pass, m1), which costs $O(n^2)$.
    • 
      

    


    

      
Recursion and the derivation (S19):

      
    
        
  • method1 → method2 → method3 is the normal pattern. A recursive method calls itself, so it has to be told which part of A to work on.
    • 
        
  • "Ceiling" slip: the lecturer said ceiling, then corrected it to floor. $\lfloor 4.5 \rfloor = 4$, so MERGE-SORT(A, 1, 8) calls (1, 4) and (5, 8), then MERGE(A, 1, 4, 8).
    • 
        
  • Padding: assuming $n = 2^k$ loses nothing. A size like 17 can be padded with dummy elements up to the next power of 2.
    • 
        
  • The lecturer called the last term "some constant". Strictly it is $(n-1)c_0$, which is $O(n)$, so the answer doesn't change.
