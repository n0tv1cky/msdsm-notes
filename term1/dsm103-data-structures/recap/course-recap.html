Foundations and the 1-D array

The vocabulary, the address formula, and the first three array operations — all written with L and U, never a language's own indexing.

VOCABULARY

data vs information
34 is data; "age = 34" is information. A value only means something once it is tied to an attribute of an entity.
ADT
Logical description: a collection of data plus the operations on it, with no word about implementation. E.g. {5, 12, 16, 7, 10} with max().
data structure
The implementation of an ADT: its physical form, built from primitives (int float char double).

THREE WAYS TO CLASSIFY

linear | non-linear
array, linked list, stack, queue | tree, graph, heap, trie (jump through links; e.g. a family tree)
homogeneous | non-homogeneous
array: one type only | struct / record: name (string) + age (int) + salary (float). Types are laid out differently in memory: int 5 → 101 with a sign bit; float 5.5 = 55×10⁻¹ → sign | exponent | mantissa; char → an unsigned code. So a slot built for one type can't hold another. (Python's mixed lists hide this in library code.)
static | dynamic
array: fixed block L…U, contiguous; free space elsewhere is useless to it | linked list: grabs scattered free blocks and links them

1-D ARRAY FORMULAS

array
a finite, ordered collection of homogeneous elements in contiguous memory
size
$\text{Size} = U - L + 1$
address (mapping function)
$\text{Addr}(A[I]) = M + (I - L)\times W$
M = base address, W = bytes per element. Special case L = 1, W = 1: $M + (I-1)$.
I-th element
sits at index $L + I - 1$

THE THREE OPERATIONS (20 AUG) — state input, output, data structure first

  • Traverse — I ← L; while I ≤ U: process A[I]; I ← I+1. O(n) time, O(1) space.
  • Bubble sort — compare only neighbours, swap when out of order; each pass parks the largest at I, then I ← I−1. Inner loop is J < I, not ≤, or A[J+1] doesn't exist. O(n²) time, O(1) space. Flip the test for descending.
  • Linear search — FOUND flag + LOCATION (start at 0, or a negative number if 0 is a valid index). Loop ends for two reasons, so test FOUND after it. Best O(1), worst O(n).

LOOPS AND INDEXING

  • while / for check the condition first; do-while runs the body once before checking. With I = 5 and condition 5 < 4: while → 0 runs, do-while → 1 run.
  • 0-based: C, Python, Java. 1-based: R vectors, SQL SUBSTRING. So write algorithms with L/U and let the formula absorb the difference.
  • Selection sort (mentioned): compare one element with all the others. Bubble sort only ever compares adjacent pairs.

Why a data scientist needs this (S01):

  • Store, manipulate, answer queries fast: a self-driving car's decision that arrives after a minute is useless.
  • Stock ticker: the highest-value stock must already be sitting at the front. If you had to scan for it, another stock would have overtaken it by the time you got there. That's why heaps and priority structures exist.
  • Printer: 10 jobs come out in firing order (a queue). Add authority levels and the boss's job jumps ahead (a priority queue).
  • Follow / follower relationships are a graph. A TF-IDF matrix is symmetric, so storing both triangles is redundant (hence module 2).
  • "No single storage structure is good for all applications": judge every choice on time and space, and expect to trade one for the other.

2-D arrays and sparse (triangular, band) matrices

      
Memory is a single line, so a grid has to be flattened. Every formula here comes from one method: count what is stored before the element.

    


    

      

        
LOGICAL vs PHYSICAL

        

          
logical
$a_{ij}$ = row $i$, column $j$ of an $m\times n$ grid (two subscripts). 1-based throughout.

          
physical
contiguous 1-D memory → a mapping formula turns $(i,j)$ into one index

          
row-major
row 1, then row 2, … — the compiler default

          
column-major
column 1, then column 2, … — you write this conversion yourself

        

      

      

        
THE ONE METHOD

        
    
          
  • Find how many elements each row (or column) stores.
    • 
          
  • Add up the complete rows (or columns) before $a_{ij}$.
    • 
          
  • Add $a_{ij}$'s position inside its own row or column, counted from that row's first stored cell, not from column 1.
    • 
          
  • That sum is the index. Then $\text{Addr} = B + (\text{Index}-1)\,w$.
    • 
          
  • Costs one multiply plus some additions, so O(1) per access.
    • 
        

      

      

        
FULL m × n

        

          
row-major
$\text{Index} = (i-1)\,n + j$
$\text{Addr} = B + [(i-1)n + (j-1)]\,w$

          
column-major
$\text{Index} = (j-1)\,m + i$
$\text{Addr} = B + [(j-1)m + (i-1)]\,w$

          
index ≠ address
5 is a position. The address is $B + (5-1)w$. Class kept mixing these up.

        

      

    


    

      

        
matrix (n × n, 1-based)stored per rowrow-major index of $a_{ij}$column-major index of $a_{ij}$

        
lower-left triangular ($j \le i$)row $i$ has $i$$\frac{i(i-1)}{2} + j$$n(j-1) - \frac{(j-1)(j-2)}{2} + (i-j+1)$

        
upper-right triangular ($j \ge i$)row $i$ has $n-i+1$$n(i-1) - \frac{(i-1)(i-2)}{2} + (j-i+1)$$\frac{j(j-1)}{2} + i$

        
diagonal ($i = j$)1$i$  (both orders agree)

        
tridiagonal ($|i-j| \le 1$)2, 3, 3, …, 3, 2$2i + j - 2$$2j + i - 2$

        
α–β band, case 1: $i \le \beta$$\alpha + i - 1$ (growing)$(i-1)\alpha + \frac{(i-1)(i-2)}{2} + j$

        
α–β band, case 2: $\beta < i \le n-\alpha+1$$\alpha+\beta-1$ (full)$\beta\alpha + \frac{\beta(\beta-1)}{2} + (i-\beta-1)(\alpha+\beta-1) + (j-i+\beta)$

Upper-right is lower-left with the roles of i and j swapped ("i will be j, j will be i"). Band: α = cells in row 1 (the diagonal plus everything to its right), β = cells in column 1 (the diagonal plus everything below). The case formulas need α + β ≤ n + 1. All formulas above were checked against a brute-force count for every n up to 9.


    

      
Why bother (S02):

      
    
        
  • A 100 × 100 array with only about 500 real values wastes about 9,500 cells. A 10,000 × 10,000 array at 8 bytes per element is 8×10⁸ bytes. Store just the band.
    • 
        
  • The price is nothing: the index formula is O(1).
    • 
        
  • This mattered most in the 512 MB RAM / 20 GB disk days. Today it still applies to band-shaped data, such as the matrices in PCA.
    • 
        
  • "You must practice this α–β band matrix." α and β are different parameters, so don't collapse them into one. Four triangle shapes exist: upper-left, upper-right, lower-left, lower-right.

Linked lists: singly and circular

      
Data goes wherever memory is free, and each node remembers where the next one is. Almost every bug comes from one of three things: where the pointer starts, which test ends the loop, or the order of two assignments.

    


    

      

        
NODE, HEADER, NULL

        

          
linked list
an ordered, finite collection of homogeneous nodes, whose linear order is kept by links

          
node
[data | link], where link = the address of the next node. Every node has the same fields.

          
header
same node type, data unused, link → first real node. It always exists, even when the list is empty.

          
NULL
the last node's link. It is the stop signal: without it you would read into memory you were never given.

          
no indexing
"node i" doesn't exist. You always walk from the header.

        

      

      

        
TWO REPRESENTATIONS

        

          
static
two parallel arrays of the same size: DATA[k] holds the value, LINK[k] holds the index of the next one. Fixed size.

          
dynamic
real pointers. getNode() returns a fresh node's address, or NULL when memory is full (overflow). With an 8 B int and an 8 B pointer, one node is 16 B.

          
ptr->data · ptr->link
the value · the address of the next node

          
GETNODE / RETURNNODE
take a block from the heap's free list / give it back. Memory is never "removed".

        

      

      

        
POINTER DISCIPLINE (the traps)

        
    
          
  • ptr = header + while ptr->link ≠ NULL stops on the last node and is safe on an empty list. Use it for insert at end, delete last, and concatenate.
    • 
          
  • ptr = header->link + while ptr ≠ NULL visits every node. Use it for traverse, search and copy.
    • 
          
  • Link the new node first, then redirect the old arrow, or you lose the rest of the list.
    • 
          
  • Deleting needs the predecessor, so use two pointers: ptr and ptr1.
    • 
          
  • A loop that can end for two reasons must be followed by a test that tells them apart: ptr->data = key.
    • 
          
  • Check getNode() = NULL before inserting, and check for an empty list before deleting.
    • 
        

      

    


    

      

        
SLL → CIRCULAR SLL (last node points back to the header)

        
    
          
  • Rule: every end-of-list NULL becomes header. So ptr ≠ header, ptr->link ≠ header, new->link ← header. Empty: header->link = header.
    • 
          
  • Insert at front: no change. It never looks for the end.
    • 
          
  • Insert at end: new->link ← header plus the loop test.
    • 
          
  • Insert after key: the mechanical conversion if ptr->link = header is wrong when the key is last. Test ptr->data ≠ key instead.
    • 
          
  • Delete first: only the underflow test changes. Delete last: three changes (underflow test, loop test, ptr1->link ← header). Delete key: two lines.
    • 
        

      

      

        
MORE OPERATIONS (S06)

        
    
          
  • Copy: a new header, then for each node getNode a fresh node, copy the data and hang it on ptr1. Two independent lists, with no arrow between them. O(n) time and O(n) space.
    • 
          
  • Concatenate: ptr = header1, walk to the last node, ptr->link = header2->link, then header2->link = NULL before RETURNNODE(header2).
    • 
          
  • Search: flag plus a location pointer. Loop while ptr ≠ NULL and flag = 0. The NULL test comes before any ptr->data, so empty lists and missing keys are safe.
    • 
        

      

    


    

      

        
singly linked listtimewhy

        
insert at front · delete firstO(1)a fixed handful of statements, no loop

Why linked lists exist (S05, S06):

      
    
        
  • Old machines often had enough free memory in total, but not in one contiguous block. So store each item wherever there is room and remember where the next one is.
    • 
        
  • Python's list "does this for you": you never manage the pointers. (Strictly, CPython's list is a resizable array of pointers, which is why indexing it is O(1). The professor's point is that Python manages the memory for you.)
    • 
        
  • S06 was taught almost entirely through questions: "I have not taught anything here, only asked questions." Expect exam questions in the same style: find the line that breaks.

Doubly linked lists and sparse matrices as multi-linked lists

      
Adding a second link per node lets you walk backwards. Adding a header link to the last node turns "insert at end" from O(n) into O(1).

    


    

      

        
DOUBLY LINKED (DLL)

        

          
node
[LLINK | DATA | RLINK]: back to the previous node, forward to the next. The order you declare the fields in doesn't matter.

          
linear DLL
header LLINK = NULL · header RLINK → first node · last node's RLINK = NULL

          
traverse
one pointer: PTR = PTR->RLINK forwards, PTR = PTR->LLINK backwards. O(n).

          
insert at front
4 links: NEW→R, NEW→L, old first's LLINK, HEADER->RLINK. Fix the old first node's LLINK before overwriting HEADER->RLINK. O(1).

        

      

      

        
CIRCULAR DOUBLY LINKED (CDLL)

        

          
shape
last node's RLINK → header, and HEADER->LLINK → last node

          
payoff
insert at end: PTR = HEADER->LLINK reaches the last node with no walk. O(n) becomes O(1).

          
loop test
PTR ≠ HEADER instead of PTR ≠ NULL

          
empty-list trap
on an empty list PTR = HEADER->RLINK = NULL, and PTR->LLINK = NEW then crashes. Give the empty case its own branch.

        

        
DLL delete, search and insert at an arbitrary position were set as self-study. They use the SLL logic plus the left links.

      

      

        
SPARSE MATRIX, MULTI-LINKED

        

          
node (5 fields)
[i | j | DATA | ROW LINK | COL LINK]: row link → next non-zero in the same row, col link → next non-zero in the same column

          
row / column headers
same structure. A zero in i or j marks a header. A row header's DATA holds that row's count of non-zeros. Its ROW LINK → the row's first element, its COL LINK → the next row header.

          
main header
stores the number of rows and columns. Its links point to RH₁ and CH₁.

          
cost
reaching $(i,j)$ means walking at most $n + n$ steps, so O(n), against O(1) for an array. Avoids the O(n²) full scan.

        

      

    


    

      
Where linked lists show up (S07):

      
    
        
  • Spotify playlist: "previous song" needs a backward link, so use a DLL. "Play in the order added" is a queue, which is an ADT: a DLL can implement it.
    • 
        
  • Insert 3 into 1 2 4 5 6 7 8: an array shifts every later element one place right, while a list just re-links two pointers. This is the linked list's key advantage.
    • 
        
  • Polynomials: nodes of [coefficient | exponent | link]. Adding or multiplying polynomials just inserts result terms as new nodes.
    • 
        
  • Free-space management: the OS chains its scattered free blocks into a linked list.
    • 
        
  • Four pointers per node (so you can also go up and left) is possible, but "a nightmare" to manage. A Sudoku grid fills every cell, so it isn't sparse: use a plain 2-D array.
    • 
        
  • The online exam's questions come "one after another and you cannot go back, just like a singly linked list".
    •

  3. Trade-off: you lose O(1) direct access, because you walk along rows and columns instead.

S08 (14 Sep) · S09 (17 Sep) — Prakash

      
Stacks and arithmetic expressions

      
A stack is an array or a linked list with one rule added: insert and delete at one end only. That rule is enough to reverse strings and evaluate expressions.

    


    

      

        
DEFINE ANY DATA STRUCTURE BY…

        
    
          
  • what data is stored (int, char, text…)
    • 
          
  • how it is arranged: linear (before/after) or non-linear (parent/child)
    • 
          
  • how it may be changed: insert, delete, update. This third rule is what makes a stack a stack rather than just an array.
    • 
        

        

          
stack
an ordered collection of homogeneous elements with insertion and deletion at one end only. LIFO: last in, first out.

        

      

      

        
ARRAY STACK (S09: 0-based, top = −1)

        

          
push(x)
full? then OVERFLOW · top ← top+1 then A[top] ← x

          
pop()
empty? then UNDERFLOW · x ← A[top] then top ← top−1

          
isEmpty · isFull
top = −1 · top = SIZE−1. With general bounds L…U (S08): empty is top < L, full is top ≥ U.

          
why −1
it's an impossible index, and −1 + 1 = 0, so the first push needs no special case

          
status (S08)
free % $= \frac{\text{size}-\text{top}}{\text{size}}\times100$

        

      

      

        
LINKED STACK

        

          
push
new←GETNODE(); new->data←item; new->link←top; top←new; stackhead->link←top

          
pop
top = NULL? then empty · item←top->data; ptr←top->link; top←ptr; stackhead->link←ptr

          
full?
meaningless, since memory is dynamic. status becomes a count of the nodes (O(n) traversal).

          
the variable new
only a local copy of an address. The node survives because top now holds that address.

        

      

    


    

      

        
NOTATIONS · PRECEDENCE

        

          
infix · prefix · postfix
a + b · + a b · a b +. Same value; only the position of the operator changes. Unary operators (++a, a++) have no infix form.

          
why postfix
(1) a stack evaluates it directly; (2) it needs no parentheses. Humans write infix, and the machine converts it, just as a compiler translates code.

          
precedence
^ > * / > + −. Brackets first, innermost first.

          
associativity
^ is right-to-left (a^b^c = a^(b^c)). * / + − are left-to-right.

        

      

      

        
POSTFIX EVALUATION (the rule to remember)

        
    
          
  • Operand: push. Operator: arg2 = pop(), arg1 = pop(), push(arg1 op arg2).
    • 
          
  • "Remember, this is important": the first pop is arg2 (the right operand). It doesn't matter for + and ×, but it decides the answer for − and ÷.
    • 
          
  • At the end exactly one value is left, and that is the answer. A pop from an empty stack means the expression was malformed (underflow).
    • 
          
  • Overflow goes with push, underflow goes with pop.
    • 
        

      

    


    

      
Analogies (S08, S09):

      
    
        
  • A stack of trays or chairs: to put one in the middle you would have to lift off the top three first. That's why a stack forbids it.
    • 
        
  • Where stacks appear: undo/redo, nested function calls (f₁ calls f₂ calls f₃…), parenthesis matching (both the count and the nesting), backtracking, syntax parsing, and string reversal (palindromes).
    • 
        
  • Multi-digit numbers on paper: 1 2 23 could be misread. Leave space or bracket them, e.g. 1 2 (23). Inside the machine each number is a separate token, so there's no ambiguity.
    • 
      

    


    

      
The stack as a bucket: one open end

      
The indices 0…3 run up the side of the bucket. Watch top move before a push stores and after a pop reads. In postfix mode, the two popped values move out to arg1 op arg2, and the result drops back in.

S10 (18 Sep) · S11 (19 Sep) — Prakash

      
Queues: linear, circular, linked

      
A queue uses two ends, each with one job: insert at the rear, delete at the front. The naive array version wastes the cells it has already served. Treating the array as a ring fixes that with pointer arithmetic alone.

    


    

      

        
QUEUE BASICS

        

          
queue
linear. Add at the rear (ENQUEUE, which takes a value), remove from the front (DEQUEUE, which takes none). FIFO: first in, first out. A stack is LIFO.

          
no update
you can't reach into the middle and change a value

          
growing restriction
array / list (insert or delete anywhere), then stack (one end), then queue (two ends, one job each)

          
pointers
stack: TOP · queue: FRONT and REAR, because the two jobs happen at different ends

        

      

      

        
ARRAY QUEUE Q[1…N] (S10)

        

          
empty
FRONT = REAR = 0. 0 is an impossible index, the same idea as the stack's −1.

          
one element · count
FRONT = REAR · REAR − FRONT + 1 (e.g. 5…10 holds 6). Linear only.

          
full
naive: REAR = N. True: FRONT = 1 AND REAR = N, which only makes sense with compaction.

          
two special cases (the exam trap)
enqueue into an empty queue also sets FRONT = 1. Dequeuing the last element (FRONT = REAR) resets both to 0.

        

      

      

        
CIRCULAR QUEUE (S11)

        

          
advance
$r = (r \bmod n) + 1$, $\;f = (f \bmod n) + 1$. When $r = n$ it gives 1; otherwise it is just $r+1$.

          
full
$(\text{rear} \bmod n) + 1 = \text{front}$: the rear sits right behind the front

          
empty
front = rear = 0. Deleting when front = rear resets both.

          
what changes
rear can be less than front, so $\text{R} - \text{F} + 1$ breaks. The capacity is still $n$: circularity adds utilisation, not space. Enqueue and dequeue are O(1).

        

      

    


    

      

        
THREE FIXES FOR THE FALSE "FULL"

        
    
          
  • 1 · Compact on full: when REAR = N but FRONT > 1, shift everything back to start at index 1, set REAR ← REAR − FRONT + 1 and FRONT ← 1, then insert. That costs O(N) whenever it happens.
    • 
          
  • 2 · Shift on every dequeue: FRONT stays at 1, so REAR = N becomes a true fullness test. Every dequeue costs O(N).
    • 
          
  • 3 · Circular: no shifting at all, so O(1). "We are just utilizing the space which is free. We are not doing anything extra to make the space free."
    • 
        

      

      

        
LINKED-LIST QUEUE

        
    
          
  • Enqueue (at the rear): new->link = NULL. If front = NULL, then front = rear = new and qhead->link = front. Otherwise rear->link = new; rear = new.
    • 
          
  • Dequeue (at the front): item = front->data; ptr = front->link; qhead->link = ptr; front = ptr. If front = NULL, also set rear = NULL.
    • 
          
  • No circular version is needed: nodes exist only for real items, so there are never idle slots. Both operations are O(1).
    • 
        

      

    


    

      

        
circular array queuelinked-list queue

        
memory reserveda fixed block of n slots up frontexactly one node per element

        
waste / capacity riskmay idle (100 slots, 10 used) or overflow (need 101)neither

        
space per elementbetter: data onlyworse: data + link

overflow · underflowinsert into a full queue · delete from an empty queue (same as a stack's push and pop)

      

    


    

      
Where queues appear (S10):

      
    
        
  • Toll booths, bank counters, grocery checkouts, traffic, and assembly lines: first come, first served.
    • 
        
  • In computing: an email server sends mail in arrival order. A multi-user server queues requests by arrival time. Printer spooling and access to memory, I/O and disk from several processes are all queues.
    • 
        
  • These are cases where you want neither an array's complete freedom nor a stack's single end. You want the order preserved.
    •

Both queues get identical operations. The data never moves: only F and R do. The ring is the circular queue's own cells 1…n bent into a circle, with the same indices. Algorithms and Big-O

      
Count steps, not seconds. Then keep only how the count grows, because constants and small inputs don't matter.

    


    

      

        
ALGORITHM

        

          
definition
a sequence of unambiguous instructions that solves a problem, giving the required output for every legitimate input in finite time

          
vs program
an algorithm is language-independent (pseudocode). A program is one implementation of it in C, Pascal, and so on. One algorithm can have many programs.

          
five characteristics
uniqueness (each step has one meaning) · finiteness (it must stop) · precision · input/output (0 or more in, at least 1 out) · generality (works for every valid input)

        

      

      

        
MEASURING

        

          
why not seconds
5 s vs 10 s says nothing, because the CPU, disk, instruction set and compiler all differ. Count elementary steps, assuming each takes the same constant time.

          
T(n)
steps as a function of input size n. Time complexity and space complexity (memory) together make up computational complexity.

          
asymptotic
behaviour as $n \to \infty$. Adding 5 numbers costs nothing, but adding a million numbers matters.

        

      

      

        
BIG-O

        

          
definition
$f(n) = O(g(n))$ if there exist $c > 0$ and $n_0$ with $f(n) \le c\,g(n)$ for all $n \ge n_0$

          
meaning
an upper bound, up to a constant. Where the curves cross for small $n$ doesn't matter. Ω and Θ were named but not defined yet.

          
rule of thumb
keep the highest-order term and drop the constants: $2n^2+3n+5 \to O(n^2)$, $2n+c \to O(n)$, $3n\log n + 5n + 20 \to O(n\log n)$

        

      

    


    

      

        
ordernameexample from the course

        
O(1)constantmin/max of a sorted array (a₁, aₙ) · insert at the front of a linked list · push/pop · circular enqueue

        
O(log n)logarithmicbinary search

        
O(n)linearvector addition · max of an unsorted array · traversal · linear search

        
O(n log n)"poly-logarithmic" in lecture; linearithmic in most textbooksmany sorting algorithms (after the midterm)

        
O(n²)quadraticbubble sort · scanning every cell of an n × n matrix

      

    


    

      
The intuition (S07 primer, S10):

      
    
        
  • Two machines add vectors at 1 s and 2 s per step: $T_1 = c_1 n$ and $T_2 = c_2 n$. Different slopes, but both grow linearly, so they count as the same performance.
    • 
        
  • Doubling a sorted array doesn't change how you find its min or max: O(1). An unsorted max needs every element, because the biggest might be last: O(n).
    • 
        
  • A random-number generator takes zero inputs and still counts as an algorithm. An even/odd checker that only works up to 100 lacks generality.
    • 
        
  • Dr. Dey kept the formal definition for later: "those mathematical formulations will be taught by Professor Surya."
    •

Slide c until the teal bound c·g(n) stays above the amber f(n) from some point on. That point is n₀. Dots are f at whole numbers of n: teal where the bound holds, red where it fails.
