## 1. Overview

This session moves from the **linear data structures** covered so far (array, linked list, stack, queue) to the first **non-linear** one: the **tree**. It starts with why trees are non-linear and gives two motivating examples: a family tree and an expression tree. Next it defines the core vocabulary: node, edge, parent, child, root, leaf, level, height, degree/arity, and sibling. It then gives the formal recursive definition of a general tree and a parenthesized string representation of one. The focus then narrows to **binary trees**: their recursive definition and three special types (complete, almost complete, strictly binary). The session ends with several standard binary tree properties, each with a short derivation:

- the maximum number of nodes on a level
- the maximum and minimum number of nodes for a given height
- the relation between edges and nodes
- the height of a complete or almost complete tree
- the relation $n_0 = n_2 + 1$

The next lecture covers how to represent binary trees using arrays and linked nodes.

## 2. Topics Covered (in order taught)

### 2.1 Linear vs. Non-Linear Data Structures

- **Linear structures** (array, linked list, stack, queue) keep data in a sequence. You access the elements one after another.
- **Linked list caveat:** linked-list nodes are *not* contiguous in memory, because nodes are linked wherever free memory exists. However, access is still **sequential**: you must follow node after node.
- **Tree (non-linear):** data is organized hierarchically, not sequentially.
  - Access does not have to be one-after-another. Depending on the logic, you might go to the left side first, then the right side, and so on.
  - The data is also not stored contiguously in memory.

### 2.2 Real-World Examples of Trees

**(a) Family tree** (diagram described)
- The top level holds the grandfather and grandmother.
- The next level holds uncle, aunt, mother and father.
- The level below holds cousins, brother, and "you".
- This illustrates the defining feature of a tree: it maintains a **hierarchy**.

**(b) Expression tree** (diagram described)
- An arithmetic expression can be stored as a tree whose shape encodes the order of evaluation. This removes the need for parentheses.
- **Internal nodes** hold **operators**.
- **Leaf nodes** (bottom nodes with no further branches) hold **operands** (numbers).
- **Worked example as described in lecture.** Operations are listed from the bottom of the tree to the top:
  1. **Bottom level:** $6 \div 2$ is evaluated first.
  2. **Next level up:** $+$ adds that result to $3$, giving $(6 \div 2) + 3$.
  3. **Next level up:** $\times$ multiplies that result by $2$, giving $((6 \div 2) + 3) \times 2$.
  4. **Root:** a division operator $\div$ is applied to that result.

  - In general form: $\big(((6 \div 2) + 3) \times 2\big) \div (\ldots)$
- Applying **inorder, preorder, and postorder traversal** to an expression tree gives the **infix, prefix, and postfix** forms of the expression. These traversals will be covered in a later lecture.

### 2.3 Basic Terminology

**Node**
- The main component of a tree. It stores the data plus link(s) to its children.
- For a **binary tree**, each node has **three components**:
  1. a `data` field
  2. a `left` child pointer
  3. a `right` child pointer

  ```
  struct Node {
      data            // the stored value
      Node* left      // pointer to left child
      Node* right     // pointer to right child
  }
  ```

- **Contrast with a doubly linked list:** both have two pointers per node.
  - In a doubly linked list, the pointers mean *previous* and *next*.
  - In a binary tree, they mean *left child* and *right child*.
  - Each child can have two children of its own, so the structure grows exponentially in both directions.

**Definitions**

| Term | Definition | Example given |
|---|---|---|
| **Parent** | The **immediate predecessor** of a node | Parent of C is A |
| **Child** | The **immediate successor** of a node | M is a child of J; G is a child of C |
| **Edge / Link / Branch** | A **pointer** from one node to another. You follow edges to move through the tree | — |

| **Leaf node (external node)** | A node with **no children** | H, I, M, K, L |
| **Level** | Root is at level $0$. If a node is at level $L$, its children are at level $L+1$ | If C is at level $1$, its children are at level $2$ |
| **Height** | The **maximum number of nodes** on any path from the root to a leaf | See the worked example below |
| **Degree / Arity** | The **maximum possible number of children** a node can have | Degree 2 means a binary tree |
| **Siblings** | Nodes with the **same parent** | J and K are siblings; I and J are not (they are "cousins") |

**Why the root matters for algorithms**
- Every tree algorithm or operation is passed **only the root**. All other nodes are reached from it.
- This is analogous to passing only the **head node** of a linked list.

**Level convention for this course**
- Some textbooks start levels at 1.
- **In this course, the root is always at level $0$.** Below it come levels $1, 2, 3, 4, \ldots$
- The top level has the smallest number; the deepest level has the largest.

**Worked example: height**
- Path A → B → D → H has **4 nodes**.
- Path A → B → D → I also has **4 nodes**.
- Path A → C → F → J → (leaf) has **5 nodes**, the maximum.
- So the height of the tree is **5**.
- The deepest leaf is at level $4$, which confirms the general relation:

$$h = (\text{maximum level}) + 1 \quad\Rightarrow\quad 4 + 1 = 5$$

**Degree, arity, and n-ary trees (from a student Q&A)**
- If nodes can have **2** children, the tree is **binary**. If **3**, it is **ternary** (3-ary). In general, it is an **n-ary** tree.
- The type is decided by the **maximum possible** number of children, not by how many children actually exist.
  - A binary tree that currently has only one node is still a binary tree, not a "1-ary" tree.
  - Children can be added later as data arrives.
- The maximum number of children a node can have is its **degree**. This term is also used as the **degree of the tree**.

### 2.4 Formal (Recursive) Definition of a Tree

A **tree** is a **finite set of one or more nodes** such that:
1. There is a specially designated node called the **root**.
2. The remaining nodes are partitioned into $n \ge 0$ **disjoint** sets $T_1, T_2, \ldots, T_n$, where **each $T_i$ is itself a tree**. These are called the subtrees of the root.

Key points about this definition:
- It is **recursive**: the same definition applies to each $T_i$.
- Under this definition a tree has at least one node, the root.
- The transcript says a tree with only a root is called "empty". That is an ASR or speech slip.
  - A root-only tree is a single-node tree.
  - An *empty* tree (zero nodes) is allowed only in the **binary tree** definition below.

**Worked example (12-node tree)**
- Nodes: A, B, C, D, E, F, G, H, I, J, K, L. This is 12 nodes, a finite number.
- The root is **A**.
- The other 11 nodes split into **3 disjoint subtrees** with no common nodes:
  - **$T_1$:** rooted at **B**, with 5 nodes: B, E, F, K, L.
    - B has two subtrees, $T_{11}$ = {E} and $T_{12}$ = {F, K, L}.
    - F has children K and L.
  - **$T_2$:** rooted at **C**, with one child G.
  - **$T_3$:** rooted at **D**, with children H, I, J.
- Each of $T_1$, $T_2$, $T_3$ satisfies the tree definition again. For example, $T_1$ is finite, has root B, and is partitioned into disjoint subtrees.

### 2.5 String (Parenthesized) Representation of a Tree

**Format:** write the root, then its subtrees in parentheses separated by commas:

$$\text{root}\,(T_1, T_2, \ldots, T_n)$$

Then expand each subtree recursively. A leaf is written as just its label.

**Steps for the 12-node example:**
1. Top level: $A\,(T_1, T_2, T_3)$
2. Expand $T_1$ (root B, subtrees E and $T_{12}$): $T_1 = B\,(E, T_{12})$
3. Expand $T_{12}$ (root F, leaves K and L): $T_{12} = F\,(K, L)$
4. Expand $T_2$: $T_2 = C\,(G)$
5. Expand $T_3$: $T_3 = D\,(H, I, J)$

**Final string representation:**

$$A\,\big(B\,(E,\; F\,(K, L)),\;\; C\,(G),\;\; D\,(H, I, J)\big)$$

### 2.7 Definition of a Binary Tree

A **binary tree** is a special form of tree with at most 2 children per node. Defined recursively:
- It is either **empty** (no nodes), giving the **empty binary tree**,
- **or** it consists of a designated **root** plus **two disjoint** binary trees:
  - $T_1$, the **left subtree**
  - $T_2$, the **right subtree**

Each of $T_1$ and $T_2$ is again a binary tree, recursively.

*Example (slide):* the root is A. The remaining nodes split into $T_1$ (rooted at B) and $T_2$. Each of these again splits into two disjoint binary subtrees.

### 2.8 Types of Binary Trees

The examples use a tree drawn with nodes numbered $1$ to $15$ level by level, which is a full 4-level tree.

**(a) Complete binary tree**
- Contains the **maximum possible number of nodes at every level**.
- Maximum nodes per level: level $0$ has $2^0 = 1$, level $1$ has $2^1 = 2$, level $2$ has $2^2 = 4$, level $3$ has $2^3 = 8$.
- If even one node is missing, the tree is **not** complete.

**(b) Almost complete binary tree**
- **All levels except the last are completely filled.**
- The last level is **filled from left to right**, with no gaps on the left.
- *Example:* nodes $13, 14, 15$ (the rightmost three on the last level) are missing. This **is** almost complete, because the last level is filled from the left.
- *Counter-example:* a node is missing at the **left** of the last level while nodes to its right exist. This is **neither complete nor almost complete**; it is just a binary tree.

**(c) Strictly binary tree**
- **Every node has either 0 or 2 children**, never exactly 1.
- Equivalently, every non-leaf (internal) node has **non-empty left and right subtrees**.
- Leaves can appear at **any** level. Do not assume leaves are always on the last level; a leaf is simply a node with no children.
- *Example (from class discussion):*
  - Remove certain nodes so that every remaining internal node still has two children.
  - The result is strictly binary, but not complete and not almost complete.
- *Student Q&A example:*
  - With nodes $13, 14, 15$ missing, the tree **is almost complete** but **not strictly binary**.
  - The parent of node $12$ is left with only **one** child.

### 2.9 Properties of Binary Trees

**Property 1: Maximum nodes on level $L$**

$$\max \text{nodes at level } L = 2^{L}$$

- Check: level $0$ has $2^0 = 1$, level $1$ has $2^1 = 2$, level $2$ has $2^2 = 4$.
- A formal proof exists but was not covered.

**Property 2: Maximum nodes in a binary tree of height $h$**

$$N_{\max} = 2^{h} - 1$$

Derivation:
1. The maximum occurs when the tree is complete.
2. Sum the maximum nodes over levels $0$ to $L$, where $L$ is the maximum level. This is a geometric progression (GP).
   - First term: $a = 2^0 = 1$
   - Common ratio: $r = 2$
   - Number of terms: $n = L + 1$, since level $0$ is counted
3. The GP sum formula for $r > 1$ is:
$$S_n = \frac{a\,(r^{n} - 1)}{r - 1}$$
4. Substitute and simplify:
$$\sum_{i=0}^{L} 2^{i} = \frac{1\cdot(2^{L+1} - 1)}{2 - 1} = 2^{L+1} - 1$$
5. Since $h = L + 1$:
$$N_{\max} = 2^{h} - 1$$

The "$-1$" is **outside** the exponent: it is $2^{h} - 1$, not $2^{h-1}$. This was corrected in class. Also note that $2^{h-1} = 2^{L}$ is the number of nodes on the **last** level.

**Property 3: Minimum nodes in a binary tree of height $h$**

$$N_{\min} = h$$

- Height is the number of nodes on the longest root-to-leaf path. The smallest tree of height $h$ is a single chain of $h$ nodes.
- No node of that chain can be removed without reducing the height.
- Example: a chain tree of height $3$ needs at least $3$ nodes.
- Some students first answered $h + 1$. That is wrong under this course's definition of height.

**Property 4: Edges vs. nodes (non-empty binary tree)**

$$E = N - 1$$

- A tree with only the root has $0$ edges.
- Each new node attached needs exactly one new edge.
- So the number of edges is always one less than the number of nodes.

**Property 5: Height of a complete or almost complete binary tree with $n$ nodes**
1. From Property 2: $n \le 2^{h} - 1$, so $2^{h} \ge n + 1$.
   - The spoken version said "$n - 1$", but $n + 1$ is correct.
2. Taking $\log_2$ of both sides:
$$h \ge \log_2(n + 1)$$
3. For a **complete** binary tree, equality holds:
$$h = \log_2(n + 1)$$
4. For an **almost complete** binary tree:
$$h = \lceil \log_2(n + 1) \rceil$$

**Property 6: Leaves vs. degree-2 nodes**

Let:
- $n_0$ = number of leaves (0 children)
- $n_1$ = number of nodes with exactly 1 child
- $n_2$ = number of nodes with 2 children

Then:

$$n_0 = n_2 + 1$$

*Visual example from class:* $n_0 = 5$ leaves and $n_2 = 4$ two-child nodes, so $5 = 4 + 1$.

*Proof:*
1. Total nodes: $n = n_0 + n_1 + n_2$.
2. From Property 4, the number of edges is $E = n - 1$.
3. Count edges by the children of each node:
   - leaves contribute $0 \cdot n_0$
   - one-child nodes contribute $1 \cdot n_1$
   - two-child nodes contribute $2 \cdot n_2$

   This gives:
$$E = n_1 + 2n_2$$
4. Set the two edge counts equal:
$$n - 1 = n_1 + 2n_2$$
5. Substitute $n = n_0 + n_1 + n_2$:
$$n_0 + n_1 + n_2 - 1 = n_1 + 2n_2$$
6. Cancel $n_1$ and rearrange:
$$n_0 = n_2 + 1$$

## 3. Formula Summary

| Quantity | Formula |
|---|---|
| Level of a child of a node at level $L$ | $L + 1$ (root is at level $0$) |
| Height vs. maximum level | $h = L_{\max} + 1$ |
| Max nodes on level $L$ | $2^{L}$ |
| Max nodes in a binary tree of height $h$ | $2^{h} - 1$ |
| Min nodes in a binary tree of height $h$ | $h$ |
| Edges in a non-empty tree with $N$ nodes | $E = N - 1$ |
| Height of a complete binary tree with $n$ nodes | $h = \log_2(n+1)$ |
| Height of an almost complete binary tree with $n$ nodes | $h = \lceil \log_2(n+1) \rceil$ |
| Leaves vs. two-child nodes | $n_0 = n_2 + 1$ |
| GP sum used in the derivation | $S_n = \dfrac{a(r^{n}-1)}{r-1}$, for $r > 1$ |

## 4. Exam/Assignment Notes and Things to Remember

- **No exam or assignment items were explicitly flagged** in this session.
- **Course convention (likely to matter on tests):** the root is at **level 0**, and **height = number of nodes on the longest root-to-leaf path = max level + 1**. Other textbooks may use different conventions, so use this course's definitions.
- **Watch these distinctions:**
  - **Complete** means every level is full.
  - **Almost complete** means all levels except the last are full, and the last is filled left to right.
  - **Strictly binary** means every node has 0 or 2 children, with leaves possibly at any level.
  - A tree can be almost complete without being strictly binary, and vice versa.
- **Common mistake corrected in class:** the maximum node count is $2^{h} - 1$ (minus one outside the exponent). The minimum node count for height $h$ is $h$, not $h+1$.
