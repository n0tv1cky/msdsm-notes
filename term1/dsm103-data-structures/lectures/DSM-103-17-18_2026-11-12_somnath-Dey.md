# DSM-103 Data Structures: Sorting I (Bubble Sort and Selection Sort)

*Session file: DSM-103-17-18_2026-11-12_somnath-Dey. Two back-to-back sessions with a 15-minute break between them.*

---

## 1. Overview

This two-part lecture introduces **sorting**, which means arranging the elements of an array or list in ascending or descending order. It also introduces the split between **comparison-based** and **non-comparison-based** sorting techniques.

**Session 1** covers **bubble sort**:
- the idea of adjacent comparisons and swaps
- why it is called "bubble" (or "sinking") sort
- a full pass-by-pass worked example
- two versions of the algorithm: a basic one, and an improved one with a `swapped` flag and a shrinking inner loop
- a statement-count complexity analysis with best, worst and average cases

**Session 2** covers **selection sort**:
- the definition of an **in-place** sorting algorithm, and why both bubble and selection sort qualify
- the sorted/unsorted partition idea
- the "find the minimum, then swap it to the front" procedure
- the algorithm and its statement-count complexity analysis
- a comparison with bubble sort, concluding that selection sort is usually faster in practice because it performs far fewer swaps

## 2. Topics Covered (in order)

### 2.1 What is sorting?
- **Definition:** A sorting technique arranges the elements of an array or list in a specific order, either **ascending** or **descending**.
- **Input:** an unordered sequence of numbers, stored in an array or list.
- **Output:** the same numbers, rearranged into sorted order.
- The lecturer showed an unordered list going through a "sorting technique" box and coming out in ascending order.
- Two sorting techniques are covered across the two sessions: bubble sort, then selection sort.

### 2.2 Classification of sorting techniques

| Category | Idea | Examples named |
|---|---|---|
| **Comparison-based** | Elements are compared with each other to decide their order | Bubble sort, selection sort, insertion sort, quick sort, merge sort, heap sort, shell sort |
| **Non-comparison-based** | Elements are arranged without comparing them pairwise | Bucket sort, counting sort, radix sort |

- In the transcript, "shell sort" appeared as "self sort" and "radix sort" appeared as "static sort"; these are almost certainly ASR errors.
- Both algorithms in this lecture are **comparison-based**.

### 2.3 Bubble sort

#### Basic idea
- Bubble sort is also called **sinking sort**.
- The algorithm runs through the list, **compares adjacent elements**, and **swaps them if they are out of order**.
- For ascending order, a pair is out of order when the first element is greater than the second.
- **Example from the lecture:** if 20 comes before 10, then $10 < 20$, so they must be swapped to give 10, 20.

#### Pass
- A **pass** is one sweep from the first element to the end of the unsorted region, comparing positions (1,2), (2,3), (3,4), and so on.

#### Key guarantee of one pass
- After one pass, the **largest element is guaranteed to reach the last position**. Every comparison pushes the larger element one step to the right.
- The **smallest element is NOT guaranteed** to reach the front after one pass.
- **Class discussion:** a student said 2 numbers (2 and 9) were sorted after pass 1. The lecturer explained that 2 reaching the front was a coincidence. If 9 and 2 had been placed differently, 2 would not have reached the front, but 9 would still have reached the end.

#### Why the name?
- **"Bubble":** the largest element "bubbles up" to the end of the array, like a bubble rising from the bottom of a pond.
- **"Sinking":** if you sort in **descending** order, the smallest element moves to the end. This looks like something sinking from the top to the bottom.

#### Worked example
Input: $[7, 2, 9, 6, 4]$, sorted in ascending order, so $n = 5$.

**Pass 1** (unsorted region is all 5 elements):
1. Compare 7 and 2. Since $2 < 7$, swap. Array: $[2, 7, 9, 6, 4]$
2. Compare 7 and 9. They are in order, no swap.
3. Compare 9 and 6. Since $6 < 9$, swap. Array: $[2, 7, 6, 9, 4]$
4. Compare 9 and 4. Since $4 < 9$, swap. Array: $[2, 7, 6, 4, 9]$

Result: **9 is in its final place**, the last position, which is where the largest element belongs.

**Pass 2** (consider only the first 4 elements; 9 is not touched):
1. Compare 2 and 7. No swap.
2. Compare 7 and 6. Swap. Array: $[2, 6, 7, 4, 9]$
3. Compare 7 and 4. Swap. Array: $[2, 6, 4, 7, 9]$

Result: **7 (the second largest) is in the second-last position.** Comparing 7 with 9 is unnecessary.

**Pass 3** (consider only the first 3 elements):
1. Compare 2 and 6. No swap.
2. Compare 6 and 4. Swap. Array: $[2, 4, 6, 7, 9]$

Result: **6 (the third largest) is in the third-last position.**

**Pass 4** (consider only the first 2 elements):
1. Compare 2 and 4. No swap.
   - If they had been $[4, 2]$, they would have been swapped here.

**After pass 4:** only one element remains in the unsorted region. A list with one element is always sorted, so the whole array $[2, 4, 6, 7, 9]$ is sorted.

**Diagram description:** each pass is drawn as a row showing the array. The adjacent pair being compared is highlighted. The sorted "tail" on the right grows by one element per pass, and the unsorted region on the left shrinks by one.

#### General rule
- Each pass places one element in its final position.
- For $n$ elements, you need **$n-1$ passes**. After $n-1$ passes, $n-1$ elements are placed, and the one remaining element is automatically in place.

#### Algorithm, version 1 (0-indexed, indices $0 \ldots n-1$)

```
BubbleSort(list, n):            // input: unsorted list; output: sorted list
  for i = 0 to n-2:             // outer loop: controls the passes
    for j = 0 to n-i-2:         // inner loop: performs one pass
      if list[j] > list[j+1]:
        swap(list[j], list[j+1])
  return list
```

How the loop bounds work:
- **Outer loop:** $i$ runs from $0$ to $n-2$, which gives $n-1$ passes.
- **Inner loop:** $j$ runs from $0$ to $n-i-2$, so the last comparison is between `list[n-i-2]` and `list[n-i-1]`.
  - When $i = 0$ (pass 1), $j$ goes up to $n-2$. The last comparison is between positions $n-2$ and $n-1$, the true end of the array.
  - When $i = 1$ (pass 2), $j$ goes up to $n-1-2 = n-3$. The last comparison is between positions $n-3$ and $n-2$, which excludes the already-sorted last element.
- In short, $i = 0$ is the first pass, $i = 1$ is the second pass, and so on.

#### Algorithm, version 2: improved (1-indexed, indices $1 \ldots n$)

```
BubbleSort(list, n):
  for i = 1 to n-1:                  // passes
    swapped = false
    for j = 1 to n-i:                // one pass; excludes the already-sorted tail
      if list[j] > list[j+1]:
        swap(list[j], list[j+1])
        swapped = true
    if swapped == false:             // no swap in the whole pass, so the array is sorted
      break
  return list
```

This version has two optimisations:

1. **Early termination using the `swapped` flag.**
   - If an entire pass makes no swap, then no adjacent pair is out of order, so the array is already sorted. The algorithm stops.
   - **Example:** for $[2, 8, 9, 10, 12, 13]$, comparing 2 and 8 gives `list[j] > list[j+1]` false, then 8 and 9 false, and so on. `swapped` stays false, so the algorithm breaks after one pass.
   - **Example:** with 10 elements, the outer loop would normally run 9 times. If the pass at $i = 5$ makes no swaps, the algorithm stops there and saves the remaining passes.
2. **Shrinking the inner loop range.**
   - An intermediate version ran $j$ from $1$ to $n-1$ in every pass. Changing the upper limit to $n-i$ means:
     - pass 1 ($i=1$) runs $j$ from $1$ to $n-1$;
     - pass 2 ($i=2$) runs $j$ from $1$ to $n-2$;
     - and so on.
   - This excludes the elements that have already been sorted.

#### Complexity of bubble sort (statement counting)

The method is to count elementary statements, using the Big-O notation from the previous lecture. Let $T(n)$ be the number of statements executed.

- **Inner loop:** about **3 statements per iteration** (the comparison, the swap, and setting `swapped`). It runs $n - i$ times, giving $3(n-i)$ statements.
- **Outer loop body:** adds about **2 more statements** (setting `swapped = false` and the `if swapped` check).
- **Statements per outer iteration $i$:** $3(n-i) + 2$.
- **Total**, summing over $i = 1, \ldots, n-1$:

$$T(n) = \sum_{i=1}^{n-1}\big[3(n-i) + 2\big] = [3(n-1)+2] + [3(n-2)+2] + \cdots + [3(1)+2]$$

$$T(n) = 1.5\,n^2 + 0.5\,n - 2 \;\Rightarrow\; O(n^2)$$

**Rule recalled from the previous lecture:**
- If $T(n) = an^2 + bn + c$, the highest power is $n^2$, so $T(n) = O(n^2)$.
- If $T(n) = an + b$, then $T(n) = O(n)$.

**Cases:**
- **Best case: the array is already sorted.**
  - Example sequence: 10, 20, 25, 80, 87, … No swaps happen in the first pass ($i = 1$), so `swapped` stays false and the algorithm breaks.
  - Only one pass runs, so $T(n) = 3(n-1) = 3n - 3$, which is $O(n)$.
- **Worst case: the smallest element is at the last position** (for ascending order).
  - The smallest element moves only one position toward the front per pass, so all $n-1$ passes are needed.
  - This gives $O(n^2)$.
- **Average case: random order.** Not derived in class, but the result to remember is $O(n^2)$.

**Summary:**
- Bubble sort is simple and easy to implement, and it is $O(n)$ only when the input is already sorted.
- Real inputs are usually random (the average case), which is $O(n^2)$.
- $O(n^2)$ is considered **slow**, so bubble sort is impractical for most real problems. It is mainly a teaching algorithm.

### 2.4 In-place sorting algorithms

**Definition:**
- A sorting algorithm is **in-place** if it sorts the elements **within the original array space**, using only a **small, constant amount of extra (auxiliary) space**.
- "Constant" means the extra space does not depend on $n$.
- 2, 10, 20, or even 100 extra variables are still "constant", as long as their number is fixed and not related to $n$.
- If the auxiliary space grows in proportion to the number of elements, the algorithm is **not in-place**.

Whether an algorithm is in-place should be analysed for **every** sorting algorithm.

**Is bubble sort in-place? Yes.** It uses:
- the array `list` itself;
- loop indices `i` and `j`;
- the flag `swapped`;
- a `temp` variable used for swapping.

All of these are constant extra space.

**How a swap works, using a temporary variable:**

```
temp = a
a    = b
b    = temp
```

**Selection sort is also in-place.**

**From the end-of-class Q&A:** the temporary variable used for swapping counts as auxiliary space. Because it is constant, the algorithm remains in-place. Some other sorting algorithms (not covered yet) need extra space equal to $n$, which makes them not in-place.

### 2.5 Selection sort

#### Basic idea
- Selection sort is **comparison-based** and **in-place**.
- During sorting, the array is always divided into two parts:
  - a **sorted part** on the left, which starts empty;
  - an **unsorted part** on the right, which starts as the whole array.
- In each pass:
  1. **Select** the smallest element in the unsorted part.
  2. **Swap** it with the first element of the unsorted part.
  3. The sorted part grows by one element, and the unsorted part shrinks by one.
- Why the minimum? The next slot to fill is the first position of the unsorted part. In sorted order, that slot must hold the least of the remaining unsorted values.

**Diagram description:**
- The array is drawn as boxes.
- Sorted elements are shown as **blue boxes** on the left.
- The minimum of the current unsorted part is highlighted as a **yellow box**.
- In the first demo, the minimum 9 is moved to the front first, then 10, then 11, and so on. When 10 is brought forward, 16 is swapped back into 10's old position.
- With each stage the blue region grows by one.

#### Worked example (second slide)
1. **Initially:** the sorted part is empty, and the unsorted part is the whole array, whose first element is 15.
2. **Pass 1:** the minimum of the whole array is 10. Swap 10 with 15, so 10 goes to position 1 and 15 goes to where 10 was. Sorted part: $[10]$.
3. **Pass 2:** the minimum of the remaining unsorted part is 15. Swap it with the first unsorted element, which is 30. Sorted part: $[10, 15]$.
4. **Further passes:** continue the same way until only one element remains. That element is automatically in place, so **$n-1$ passes** are needed.

#### Finding the minimum (walkthrough given in class)
Use a variable `min` that stores the **index** of the current minimum, not its value. Using 1-indexed positions:

1. Start with `min = i`, assuming the first unsorted element (position 1) is the minimum.
2. Scan positions 2 and 3. Their values (for example 20 and 30) are not smaller than the current minimum, so there is no change.
3. At position 4 the value is **10**, which is smaller than the current minimum, so set `min = 4`.
4. At positions 5 and 6 the values are 15 and 17. Neither is less than 10, so there is no change.
5. At position 7 the value is **8**, which is less than 10, so set `min = 7`.
6. After scanning to the end, `min` holds the index of the true minimum. Swap `list[1]` with `list[7]`.

#### Algorithm (1-indexed)

```
SelectionSort(list, n):          // input: unsorted list; output: sorted list
  for i = 1 to n-1:              // outer loop: passes; i = position to fill
    min = i                      // assume the first unsorted element is the minimum
    for j = i+1 to n:            // inner loop: scan the rest of the unsorted part
      if list[j] < list[min]:
        min = j                  // update the index of the minimum
    if min != i:                 // swap only if the minimum is not already at position i
      swap(list[i], list[min])
  return list
```

- **Value of $i$:** $i$ always marks the first position of the unsorted part, which is where the next minimum goes.
  - $i = 1$ fills the 1st position, $i = 2$ fills the 2nd, and so on, up to $i = n-1$.
  - The last element then falls into place automatically.
- **Purpose of `if min != i`:** if the minimum is already at position $i$, no swap is needed.
- **At most one swap per pass.**

#### Complexity of selection sort (statement counting)

**Number of inner-loop iterations:** $j$ runs from $i+1$ to $n$, so the count is

$$n - (i+1) + 1 = n - i$$

To check the "last − first + 1" rule: $j$ from 2 to 10 gives $10 - 2 + 1 = 9$ values.

**Statement count:**
- **Inner loop body:** about 2 statements per iteration (the comparison and `min = j`), giving $2(n-i)$ statements.
- **Outer loop body:** about 2 more statements (the `min != i` check and the swap).
- **Statements per outer iteration $i$:** $2(n-i) + 2$.
- **Total**, summing over $i = 1, \ldots, n-1$:

$$T(n) = \sum_{i=1}^{n-1}\big[2(n-i) + 2\big] = [2(n-1)+2] + [2(n-2)+2] + \cdots + [2(1)+2]$$

This is an arithmetic series:

$$T(n) = n^2 + n - 2 \;\Rightarrow\; O(n^2)$$

**Constants don't matter:**
- If the swap is counted as 3 statements (`temp = a; a = b; b = temp`), the outer body becomes 4 statements instead of 2.
- That adds $2(n-1)$ in total:

$$T(n) = n^2 + n - 2 + 2(n-1) = n^2 + 3n - 4 \;\Rightarrow\; \text{still } O(n^2)$$

**Cases:**
- **Best case: the array is already sorted.**
  - Selection sort has **no mechanism** to detect that the array is already sorted (unlike bubble sort's `swapped` flag).
  - All comparisons still run, so the best case is $O(n^2)$.
- **Worst case: the array is in reverse order.** This is $O(n^2)$.
- **Average case: random order.** This is $O(n^2)$; it was not derived formally in class.

### 2.6 Bubble sort vs. selection sort

| Case | Bubble sort | Selection sort |
|---|---|---|
| Best | $O(n)$ | $O(n^2)$ |
| Worst | $O(n^2)$ | $O(n^2)$ |
| Average | $O(n^2)$ | $O(n^2)$ |
| In-place? | Yes | Yes |

**Discussion in class:**
- From the table alone, bubble sort looks better because its best case is $O(n)$.
- In practice, inputs are random, so the **average case** matters most. Both algorithms are $O(n^2)$ there.
- **Comparisons are about equal.** To place the next element (the next-largest at the end for bubble sort, or the next-smallest at the front for selection sort), both algorithms examine the same number of remaining elements.
- **Swaps are where they differ:**
  - Bubble sort swaps **every time an adjacent pair is out of order**, which can mean many swaps per pass.
  - Selection sort does **at most one swap per pass**, after scanning the whole unsorted part. That is at most $n-1$ swaps in total.

**Conclusion:**
- Selection sort is generally **more efficient in practice** than bubble sort, especially for large inputs, because it does fewer swaps.
- If you must choose between the two, **choose selection sort**.

## 3. Exam / Assignment Pointers

The lecturer did not explicitly flag anything for the exam. These points were stressed or posed as questions in class and are likely testable:

- **Bubble sort guarantee:** after one pass, the **largest** element is guaranteed to be at the end. The smallest is **not** guaranteed to be at the front.
- **Number of passes:** both algorithms need **$n-1$ passes** for $n$ elements.
- **Loop bounds:**
  - Bubble sort, 0-indexed: $j = 0 \ldots n-i-2$.
  - Bubble sort, 1-indexed: $j = 1 \ldots n-i$.
  - Selection sort: $j = i+1 \ldots n$, which is $n-i$ iterations.
- **The `swapped` flag** is the reason bubble sort has an $O(n)$ best case. Selection sort has no such check, so its best case is $O(n^2)$.
- **Statement-count results to remember:**
  - Bubble sort: $T(n) = 1.5n^2 + 0.5n - 2$.
  - Selection sort: $T(n) = n^2 + n - 2$ (or $n^2 + 3n - 4$ if the swap is counted as 3 statements).
  - Both are $O(n^2)$, and constant factors don't change the order.
- **In-place definition:** constant auxiliary space means in-place; auxiliary space proportional to $n$ means not in-place. Both algorithms here are in-place.
- **Practical question asked in class:** "Which is better, bubble or selection sort?" The answer is selection sort, because it makes fewer swaps.
