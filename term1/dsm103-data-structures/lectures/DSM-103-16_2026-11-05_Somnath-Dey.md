# DSM-103 Lecture 16: Graphs (Representation, Types, DFS and BFS)

**Session:** DSM-103-16, 2026-11-05, Lecturer: Somnath Dey

---

## 1. Overview

This session introduces the **graph**, a non-linear data structure. The lecturer began with real-world applications: Google Maps, social networks, computer networks, road networks and biological networks. He then defined a graph formally as $G = (V, E)$ and covered directed vs. undirected graphs, simple graphs, multigraphs, loops and pseudographs. Three ways to store a graph in a computer followed: the **adjacency list**, the **adjacency matrix** and the **incidence matrix**. For each, the class discussed how to read off degree, in-degree, out-degree and the total number of edges. Special graph families came next: complete graphs $K_n$, cycles $C_n$, $n$-dimensional hypercubes $Q_n$ and bipartite graphs. The session ended with the two graph traversals, **Depth-First Search (DFS)**, which uses a stack, and **Breadth-First Search (BFS)**, which uses a queue, each traced step by step on the same 7-vertex example. This was the lecturer's last session in this course; Professor Surya takes over from the next lecture.

## 2. Topics Covered (in order taught)

### 2.1 Applications of graphs

| Application | Vertices (nodes) | Edges |
|---|---|---|
| Computer networks | Computers, routers, switches | Physical or logical links |
| Social networks (e.g. friendship) | People | Friendship (undirected) |
| Social networks with "follow" | People | A follows B (**directed**; B need not follow A) |
| Collaboration networks (academia) | Researchers, PIs | Joint supervision or projects |
| Information networks | Servers or information sources | Information sharing |
| Software design | Components (e.g. in collaboration diagrams) | Interactions |
| Road or transportation networks, Google Maps | Cities or junctions | Roads (one-way roads become directed edges) |
| Mobile tower networks | Towers | Connections |
| Biological networks | Organs or biological entities | Relationships |

The key idea is that once a problem is modelled as a graph, standard graph algorithms can be applied to solve it.

### 2.2 Definition of a graph

A graph is a pair of sets:
$$G = (V, E)$$

- $V$ is the set of **vertices (nodes)**. It **must be non-empty**, so a graph has at least one vertex.
- $E$ is the set of **edges**. It **may be empty**.
- Each edge has two **endpoints**, the two vertices it connects.

**Example 1 (empty edge set).**
- Three isolated vertices, drawn as three dots with no lines between them.
- $V = \{v_1, v_2, v_3\}$, $E = \emptyset$.
- This is a valid graph.

**Example 2.**
- $V = \{A, B, C, D\}$.
- $E = \{AB,\ BC,\ BD,\ DC,\ AC\}$.
- Visually: $A$ connects to $B$ and $C$; $B$ connects to $A$, $C$ and $D$; $C$ connects to $A$, $B$ and $D$; $D$ connects to $B$ and $C$.

Writing a graph as a picture or as raw sets suits pen and paper. Algorithms need structured representations instead (Section 2.5), otherwise they become slow.

### 2.3 Directed vs. undirected graphs

**Undirected graph**
- Edges have no direction, so edge $DB$ is the same as edge $BD$.
- Example: two connected computers can both send data to each other.

**Directed graph (digraph)**
- Each edge is drawn as an arrow, so $(A, B)$ means you can go $A \to B$.
- You cannot go $B \to A$ unless a separate edge $(B, A)$ exists.
- Example: **one-way roads**.

### 2.4 Graph terminology: simple graphs, multigraphs, loops, pseudographs

- **Simple graph:** each edge connects two distinct vertices, and no two edges connect the same pair of vertices. There are no parallel edges and no loops.
- **Multigraph:** multiple edges may connect the same pair of vertices.
  - If $m$ different edges connect $u$ and $v$, then $\{u, v\}$ is an edge of **multiplicity $m$**.
  - Multigraphs as defined in class do **not** include loops.
- **Loop (self-loop):** an edge that starts and ends at the same vertex, e.g. an edge from $B$ to $B$.
- **Pseudograph:** a graph that may contain **both** multiple edges **and** loops.

### 2.5 Graph representations

The lecturer named three techniques: the **adjacency list**, the **adjacency matrix** and the **incidence matrix**.

#### (a) Adjacency list

- Each vertex heads a **linked list**. The other nodes in that list are its **neighbours**, the vertices you can go to directly from it.
- Diagram in words: a vertical column of head nodes $A, B, C, \dots$. Each head node has a chain of linked-list nodes extending to the right.
- **Caution stressed in class:** the order of nodes within a list implies nothing about edges between those nodes. For example, if $A$'s list is $B \to C \to E$, that does *not* mean $B$ and $C$ are connected. It only means $A$ is connected to each of $B$, $C$ and $E$.
- **Limitation (per lecture):** the adjacency list was presented as unsuitable for **multiple edges**, because you would have to list the same neighbour twice.
- It can also be drawn as a **table**: the first column holds the vertex and a second column holds its adjacent vertices.

**Undirected example**, as dictated. The transcript is partly garbled, so check it against the slide.

| Vertex | Adjacent vertices |
|---|---|
| A | B, C, E |
| B | A *(likely also E, since E lists B)* |
| C | A, E, D |
| D | E, C |
| E | B, C, A *(likely also D, since D lists E)* |

In an **undirected** graph, the lists are symmetric: if $B$ is in $A$'s list, then $A$ is in $B$'s list.

**Directed example** (only vertices A–D were worked; the transcript is garbled):

| Vertex | Out-neighbours |
|---|---|
| A | B, E, D |
| B | B *(self-loop)*, D, C, E. $A$ is **not** listed because there is no edge $B \to A$. |
| C | A, E (possibly C) |
| D | *(none, or unclear)* |

In a **directed** graph the lists are not necessarily symmetric.

#### (b) Adjacency matrix

Build an $n \times n$ matrix $M$, where $n = |V|$:
$$M[i][j] = \begin{cases} 1 & \text{if there is an edge between vertex } i \text{ and vertex } j \\ 0 & \text{otherwise} \end{cases}$$

**Undirected example.** The graph has 4 vertices and edges $AB$, $AC$, $AD$, $BC$. In words, $A$ is joined to all three other vertices, $B$ and $C$ are joined, and $D$ hangs off $A$ only.

| | A | B | C | D |
|---|---|---|---|---|
| **A** | 0 | 1 | 1 | 1 |
| **B** | 1 | 0 | 1 | 0 |
| **C** | 1 | 1 | 0 | 0 |
| **D** | 1 | 0 | 0 | 0 |

- **Undirected graph:** the matrix is **symmetric** ($M = M^T$). You only need to store one triangular half.
- **Directed graph:** $M[i][j] = 1$ if there is an edge $i \to j$. The matrix is generally **not symmetric**, so the full matrix must be stored. The class did a directed version of the same graph; its diagonal was 0 because it had no loops, but the exact entries are not recoverable from the transcript.
- **Pseudograph / multigraph:**
  - $M[i][j]$ = the **number of edges** between $i$ and $j$, i.e. the multiplicity. For example, 3 parallel edges between $A$ and $B$ give $M[A][B] = 3$.
  - A **loop** at $C$ puts a nonzero value on the diagonal. The lecture said 1.
  - Reading the cell values tells you directly how many edges join two vertices.

#### (c) Incidence matrix

- **Rows** are vertices $v_1, \dots, v_n$; **columns** are edges $e_1, \dots, e_m$.
- $M[v][e] = 1$ if edge $e$ is incident to (touches) vertex $v$, and 0 otherwise.
- For example, if edge $e_1$ connects $v_1$ and $v_4$, then cells $(v_1, e_1)$ and $(v_4, e_1)$ are 1.
- **Property:** each column contains exactly **two 1s**, one for each endpoint of a non-loop edge.
- The **row sum** for vertex $v$ is the number of edges incident to $v$, i.e. its degree.
- You *can* read off which vertices an edge connects. You *cannot* get that per-edge information from an adjacency matrix, because the matrix has no edge identities. Choose the representation based on what your application needs.

### 2.6 Neighbours, degree, in-degree, out-degree

**Neighbours**
- The neighbours of $v$ are the vertices adjacent to $v$.
- The set of all neighbours is denoted $N(v)$.

**Degree (undirected)**
- $\deg(v)$ is the number of edges incident to $v$.
- Class example: $\deg(A) = \deg(B) = \deg(C) = 4$ in the slide graph. For $C$, the edges were counted "1, 2, 3, 4".

**Directed graphs** split degree into two parts:
- **In-degree** $\deg^-(v)$: the number of edges coming **into** $v$.
- **Out-degree** $\deg^+(v)$: the number of edges going **out of** $v$.
- Notation: the superscript minus means in-degree and the superscript plus means out-degree.

**Computing degrees from each representation**

| Representation | Undirected degree | Out-degree | In-degree |
|---|---|---|---|
| Adjacency matrix | Row sum (equals column sum) | **Row** sum | **Column** sum |
| Adjacency list | Length of $v$'s list | Length of $v$'s list (easy) | Must **scan every list** for occurrences of $v$, which is costly (e.g. 1000 vertices means searching all lists) |
| Incidence matrix | Row sum | Readable from row and column data | Readable from row and column data |

The class worked a directed example: vertex $A$ has 3 incident edges, of which 2 are outgoing and 1 is incoming.

**Conclusion given in class:** if you frequently need in-degree, prefer an adjacency matrix or incidence matrix over an adjacency list.

### 2.7 Counting edges from a matrix (in-class Q&A)

- **Undirected graph, adjacency matrix:**
  $$|E| = \frac{1}{2}\sum_{i}\sum_{j} M[i][j]$$
  Each edge appears twice, at $(i, j)$ and at $(j, i)$.
- **Directed graph, adjacency matrix:**
  $$|E| = \sum_{i}\sum_{j} M[i][j]$$
  Each edge appears once, since the matrix is not symmetric.
- **Incidence matrix:**
  $$|E| = \frac{1}{2}\sum_{v}\sum_{e} M[v][e]$$
  Each column (edge) contributes two 1s. More directly, $|E|$ is the number of columns.

The lecturer said he would **not cover** the "second theorem" on the slides. That is likely the Handshaking Theorem, $\sum_{v \in V} \deg(v) = 2|E|$, which the edge-count result above reflects.

### 2.8 Special types of graphs

**Complete graph $K_n$**
- Every pair of the $n$ vertices is connected by an edge.
- Examples: $K_1$ is a single vertex, $K_2$ is two vertices with one edge, and $K_3$ is a triangle. $K_4$, $K_5$ and $K_6$ were also shown.
- Standard fact, not stated in class: $K_n$ has $\frac{n(n-1)}{2}$ edges.

**Cycle $C_n$**
- Vertices $v_1, v_2, \dots, v_n$ with edges $v_1v_2,\ v_2v_3,\ \dots,\ v_{n-1}v_n,\ v_nv_1$.
- Requires $n \ge 3$.

**$n$-dimensional hypercube $Q_n$**
- There are $2^n$ vertices, each labelled by an $n$-bit binary string.
- Two vertices are adjacent **iff their labels differ in exactly one bit**.
- Example ($Q_3$): $000$ is adjacent to $001$, $010$ and $100$. Labels $001$ and $011$ differ in exactly one bit, so they **are** adjacent. Labels $001$ and $010$ differ in two bits, so they are **not** adjacent.
- Visually, $Q_3$ is a cube.

**Bipartite graph**
- $V$ can be partitioned into two disjoint sets $V_1$ and $V_2$ such that every edge has one endpoint in $V_1$ and the other in $V_2$.
- There are **no edges within $V_1$** and **no edges within $V_2$**.
- The class example had vertices $A$ to $G$. The first attempted partition failed. A valid one was:
  $$V_1 = \{A, B, D\}, \qquad V_2 = \{C, E, F, G\}$$
  - Edges run only between the groups, for example $B$–$F$, $B$–$C$, $B$–$E$ and $D$–$C$. Per the dictation, $A$ was also joined to vertices in $V_2$.
  - There is no edge $G$–$F$, $G$–$E$, $F$–$C$, $C$–$E$, and so on within $V_2$, and no edge within $V_1$.

### 2.9 Graph traversal: DFS and BFS

The goal is to start at a given vertex and visit all reachable vertices. The lecture covered only how to *perform* the traversals, not their theoretical proofs.

- **DFS (Depth-First Search):** go as deep as possible along a path. When stuck, **backtrack** and try other unexplored edges. It uses a **stack**.
- **BFS (Breadth-First Search):** visit all the closest neighbours of the current vertex first, then their neighbours, and so on, level by level. It uses a **queue**.

The lecturer briefly misspoke ("for DFS we use queue") and then corrected himself: **DFS uses a stack, BFS uses a queue.**

In an exam you will usually be given the **adjacency list or adjacency matrix**, not the picture.

#### The example graph (used for both traces)

The edges below are reconstructed from the neighbour lists used during the traces:

$$E = \{AB,\ AD,\ AE,\ BC,\ BE,\ DE,\ CE,\ EF,\ FC,\ FG,\ GC\}$$

Neighbour lists:

| Vertex | Neighbours |
|---|---|
| A | B, D, E |
| B | A, C, E |
| C | B, E, F, G |
| D | A, E |
| E | A, B, C, D, F |
| F | C, E, G |
| G | C, F |

Picture description: $E$ is a central hub joined to $A$, $B$, $C$, $D$ and $F$. $A$ is also joined to $B$ and $D$, and $B$ is joined to $C$. $F$, $G$ and $C$ form a triangle.

#### DFS algorithm (stack-based)

Three things are tracked: a **stack**, a **visited** set and the **output** sequence.

```
DFS(G, start):
    stack ← empty;  visited ← ∅;  output ← []
    push(stack, start)
    while stack not empty:
        v ← pop(stack)
        if v ∈ visited: continue          // discard already-visited nodes
        visited ← visited ∪ {v}
        append v to output
        for each neighbour w of v:
            if w ∉ visited: push(stack, w)
    return output
```

#### DFS trace from A

Convention: the stack is written left to right, and the **rightmost element is the top** (the one popped next).

| Step | Pop | Action | Output so far | Stack after step |
|---|---|---|---|---|
| 1 | — | push A | — | A |
| 2 | A | visit A; push unvisited neighbours B, D, E | A | B D E |
| 3 | E | visit E; push unvisited neighbours D, B, C, F (A already visited) | A E | B D D B C F |
| 4 | F | visit F; push C, G (E visited) | A E F | B D D B C C G |
| 5 | G | visit G; push C (F visited) | A E F G | B D D B C C C |
| 6 | C | visit C; its neighbours B, E, F, G are already visited or already on the stack | A E F G C | B D D B C C |
| 7–8 | C, C | already visited, so discard | A E F G C | B D D B |
| 9 | B | visit B. This is the **backtracking** step. | A E F G C B | B D D |
| 10 | D | visit D | A E F G C B D | B D |
| 11–12 | D, B | already visited, so discard | — | *(empty)* |

**DFS output: $A, E, F, G, C, B, D$.**

Path interpretation:
1. The search goes $A \to E \to F \to G \to C$.
2. It then reaches $B$. From $B$ it cannot go anywhere new.
3. It backtracks through $G$, then $F$, then back to $E$.
4. From $E$ it explores $D$.

Popping stale duplicate entries and discarding them is the stack's way of **backtracking**.

#### BFS algorithm (queue-based)

A **queue** is FIFO: you enqueue at the **rear** and dequeue from the **front**.

```
BFS(G, start):
    queue ← empty;  visited ← ∅;  output ← []
    enqueue(queue, start)
    while queue not empty:
        v ← dequeue(queue)
        if v ∈ visited: continue
        visited ← visited ∪ {v}
        append v to output
        for each neighbour w of v:
            if w ∉ visited: enqueue(queue, w)
    return output
```

#### BFS trace from A

The queue is written front to rear, left to right.

| Step | Dequeue | Action | Output so far | Queue after step |
|---|---|---|---|---|
| 1 | — | enqueue A | — | A |
| 2 | A | visit; enqueue B, D, E | A | B D E |
| 3 | B | visit; enqueue E, C (A visited) | A B | D E E C |
| 4 | D | visit; enqueue E (A visited) | A B D | E E C E |
| 5 | E | visit; enqueue C, F (D, A, B visited) | A B D E | E C E C F |
| 6 | E | already visited, so skip | A B D E | C E C F |
| 7 | C | visit; enqueue G (B, E, F visited or queued) | A B D E C | E C F G |
| 8–9 | E, C | already visited, so skip | — | F G |
| 10 | F | visit | A B D E C F | G |
| 11 | G | visit | A B D E C F G | *(empty)* |

The lecturer stopped at step 7 with output A, B, D, E, C. Steps 8–11 are completed here using the same rules.

**BFS output: $A, B, D, E, C, F, G$.** This is level-wise:
- Level 0: $A$.
- Level 1: $B$, $D$, $E$.
- Level 2: $C$, $F$.
- Level 3: $G$.

**Student Q&A clarification.** Writing the output as "A → B → D" does **not** mean there is an edge $B$–$D$. The arrows only show the **visiting order**. Write the output with commas ($A, B, D, \dots$) to avoid this confusion.

#### Non-uniqueness of traversals (Q&A)

DFS and BFS orders are **not unique**. They depend on the order in which neighbours are pushed or enqueued.
- Pushing A's neighbours in a different order would make DFS go $A \to B$ first instead of $A \to E$.
- From $B$, it could then go to $C$ or to $E$, giving yet another sequence.
- So one graph can have **multiple valid DFS sequences and multiple valid BFS sequences**.

#### Complexity

Not stated in the lecture; these are standard values for reference:
- Time with an adjacency list: $O(|V| + |E|)$.
- Time with an adjacency matrix: $O(|V|^2)$.
- Extra space for the stack or queue plus the visited set: $O(|V|)$.
- Storage for the representations: the adjacency matrix needs $O(|V|^2)$ space and the adjacency list needs $O(|V| + |E|)$.

## 3. Exam and Assignment Notes

- **Assigned practice:** "Complete these two examples using DFS and BFS." Run both traversals fully on the two example graphs from the slides, showing the stack or queue, the visited set and the output at each step.
- **Likely exam format:** you will be given an **adjacency list or adjacency matrix**, not a picture, and asked to perform a DFS or BFS from a given start vertex.
- **Points to get right:**
  - DFS uses a **stack** (LIFO); BFS uses a **queue** (FIFO).
  - Always check whether a popped or dequeued node is already visited, and discard it if so.
  - Traversal orders are **not unique**. State your neighbour-ordering convention.
  - Write output sequences with commas, not arrows.
  - Know how to get degree, in-degree and out-degree from each representation: row sum and column sum in a matrix, list length in an adjacency list.
  - Know the edge counts: undirected adjacency matrix gives $\frac{1}{2}\sum M[i][j]$; directed adjacency matrix gives $\sum M[i][j]$; incidence matrix gives $\frac{1}{2}\sum$ of all entries.
  - Know the definitions of simple graph, multigraph, loop, pseudograph, $K_n$, $C_n$ (with $n \ge 3$), $Q_n$ and bipartite graph.
