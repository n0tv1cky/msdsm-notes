## 1. Overview

This lecture continues from the previous session on binary tree properties and types. It covers two ways to store a binary tree.

- **Array (sequential) representation:** nodes are stored level by level. Index formulas give the left child, right child and parent. This is efficient for complete or almost complete trees but wastes a lot of memory for skewed trees.
- **Linked representation:** each node holds a left-child pointer, a data field and a right-child pointer. This is space efficient.

Because a tree is non-linear, it needs defined **traversal** orders. The instructor lists all six possible orderings of (root, left subtree, right subtree). He then focuses on **pre-order, in-order and post-order**, using an **expression tree** to show that these give the prefix, infix and postfix expressions. The class discusses operator precedence and associativity in expression trees.

Next comes **reconstructing a tree from traversal sequences**. In-order must be combined with either pre-order or post-order. Two worked examples are given. The session ends by classifying expression trees (strictly binary, complete, almost complete).

Binary search trees (search, insert, delete) were planned but **deferred to the next lecture**.

## 2. Topics Covered (in order taught)

### 2.1 Array Representation of a Binary Tree

**Idea:** Store nodes **level-wise**. The root (top level) goes first, then its children, then the next level, and so on, left to right.

**Indexing formulas (assumption: array index starts at 1).** If a node is stored at index $`i`$:

| Quantity | Formula |
|---|---|
| Left child index | $`2i`$ |
| Right child index | $`2i + 1`$ |
| Parent index | $`\left\lfloor \dfrac{i}{2} \right\rfloor`$ (integer division) |

- The instructor stressed that these rules change if indexing starts at 0.
- *(Supplementary, 0-based version:)* left child $`= 2i+1`$, right child $`= 2i+2`$, parent $`= \left\lfloor \dfrac{i-1}{2} \right\rfloor`$.

**Worked example (example tree).**

Tree structure in words:
- The root is **15**.
- Its left child is **10** and its right child is **20**.
- 10 has left child **8** and right child **12**.
- 20 has left child **16** and right child **25**.

```
            15
          /    \
        10      20
       /  \    /  \
      8   12  16   25
```

| Index | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
|---|---|---|---|---|---|---|---|
| Value | 15 | 10 | 20 | 8 | 12 | 16 | 25 |

Steps used in class:
- 15 is at index 1.
  - Its left child is at $`2 \times 1 = 2`$, which holds 10.
  - Its right child is at $`2 \times 1 + 1 = 3`$, which holds 20.
- 10 is at index 2.
  - Its left child is at $`2 \times 2 = 4`$, which holds 8.
  - Its right child is at $`2 \times 2 + 1 = 5`$, which holds 12.
- 20 is at index 3.
  - Its left child is at $`3 \times 2 = 6`$, which holds 16.
  - Its right child is at $`3 \times 2 + 1 = 7`$, which holds 25.

**Finding the parent (class discussion).**
- Students first proposed separate rules:
  - For **odd** $`i`$: parent $`= \dfrac{i-1}{2}`$.
  - For **even** $`i`$: parent $`= \dfrac{i}{2}`$.
- Parent of **12** (index 5, odd): $`\dfrac{5-1}{2} = 2`$. Index 2 holds 10. ✔
- Parent of **8** (index 4, even): $`\dfrac{4}{2} = 2`$. ✔
- The instructor asked for a single generic formula. The answer is $`\left\lfloor i/2 \right\rfloor`$ using **integer division**, which takes the floor.
  - Example: $`5/2`$ under integer division gives $`2`$, not $`2.5`$ or $`3`$.

**Advantage:** accessing a child or parent is simple arithmetic, so it is $`O(1)`$.

**Problem: memory wastage for non-complete (e.g. skewed) trees.**

Worked example with a **right-skewed tree** 2 → 10 → 13 → 16. Each node is the right child of the previous one.

| Node | Index | Calculation |
|---|---|---|
| 2 | 1 | root |
| 10 | 3 | $`2 \times 1 + 1`$ |
| 13 | 7 | $`2 \times 3 + 1`$ |
| 16 | 15 | $`2 \times 7 + 1`$ |

- Indices 2, 4, 5, 6, 8–14 are **blank**. That is 11 of 15 slots wasted to store only 4 nodes.
- The array must be declared big enough for a **full/complete binary tree of that height**:

```math
\text{array size} = 2^{h} - 1
```
  where $`h`$ is the height counted as the number of levels.
  - Here the levels are 1, 2, 3, 4, so $`h = 4`$ and the size is $`2^4 - 1 = 15`$.
  - (The instructor first said 3 and then corrected himself to 4.)
- **Conclusion:** the array representation is fine if the tree is **complete or almost complete**. Otherwise it wastes a lot of memory.

### 2.2 Linked Representation (Node-and-Pointer Structure)

The instructor noted that this is not literally a linked list. It is a node structure with pointers.

**Node structure, with three fields:**

```
+--------+--------+--------+
|  LC    |  DATA  |  RC    |
+--------+--------+--------+
LC   = pointer to left child
DATA = the node's value
RC   = pointer to right child
```

```c
struct Node {
    struct Node *LC;   // left child pointer
    int data;          // node value
    struct Node *RC;   // right child pointer
};
```

**The example tree as a pointer diagram (in words):**
- Root node holds **15**.
  - Its LC points to node **10**.
    - Node 10's LC points to node **8**. Both of 8's pointers are NULL.
    - Node 10's RC points to node **12**. Both of 12's pointers are NULL.
  - Its RC points to node **20**.
    - Node 20's LC points to node **16**. Both of 16's pointers are NULL.
    - Node 20's RC points to node **25**. Both of 25's pointers are NULL.

**Space efficiency:** nodes are created only as needed. For the right-skewed tree, only the nodes that actually exist are allocated, with no blank slots. The linked representation is therefore the **space-efficient representation**.

### 2.3 Tree Traversal

**Why traversal needs rules:** a tree is a **non-linear** data structure. Data are not stored sequentially, so a specific rule is needed to visit every node.

**Recursive definition of a tree:** a tree is a root $`R`$, a left subtree $`T_L`$ and a right subtree $`T_R`$. Each subtree is itself a root with left and right subtrees. The visiting pattern is applied recursively until a leaf is reached.

**All six possible orders:**

| # | Order | Name |
|---|---|---|
| 1 | $`R,\ T_L,\ T_R`$ | **Pre-order** |
| 2 | $`T_L,\ R,\ T_R`$ | **In-order** |
| 3 | $`T_L,\ T_R,\ R`$ | **Post-order** |
| 4 | $`T_R,\ T_L,\ R`$ | Reverse pre-order (exact reverse of pre-order) |
| 5 | $`T_R,\ R,\ T_L`$ | Reverse in-order |
| 6 | $`R,\ T_R,\ T_L`$ | Reverse post-order |

Orders 4–6 are just reverses of 1–3, so the course **focuses on pre-order, in-order and post-order**.

**Algorithms (recursive pseudocode):**

```
PREORDER(T):
  if T == NULL: return
  visit(T.data)
  PREORDER(T.LC)
  PREORDER(T.RC)

INORDER(T):
  if T == NULL: return
  INORDER(T.LC)
  visit(T.data)
  INORDER(T.RC)

POSTORDER(T):
  if T == NULL: return
  POSTORDER(T.LC)
  POSTORDER(T.RC)
  visit(T.data)
```

*(Supplementary:)* each traversal takes $`O(n)`$ time because every node is visited once. It uses $`O(h)`$ extra space for the recursion stack, where $`h`$ is the tree height. In the worst case (a skewed tree) that is $`O(n)`$.

**How to do it by hand (clarified during class Q&A):**
- This is *not* simply "bottom-up then top-down."
- Start at the root and keep going down the left side until you reach a leaf.
- Finish the entire left subtree, then handle the root, then the right subtree, depending on the order.
- Apply the same rule inside every subtree.

### 2.4 Expression Trees and Traversals

**Expression tree:** operators are at internal (parent) nodes and operands are at the leaves (children).
- Simple example: $`A + B`$ is a root `+` with left child `A` and right child `B`.

**Memory aid:**

| Traversal | Gives | Reason |
|---|---|---|
| In-order | **Infix** expression | Operator is "in" the middle |
| Pre-order | **Prefix** expression | Operator comes first |
| Post-order | **Postfix** expression | Operator comes last |

**Main example tree (in words):**
- The root is `+`.
- The left subtree has root `−`, with left child `A` and right child `B`.
- The right subtree has root `*`.
  - The left child of `*` is `C`.
  - The right child of `*` is `/`, with left child `E` and right child `F`.

```
            +
         /     \
        −       *
       / \     / \
      A   B   C   /
                 / \
                E   F
```

This represents $`(A - B) + \big(C * (E / F)\big)`$.

**In-order traversal, step by step:**
1. From `+`, go left to `−`, then left again to `A`. A has no left child, so visit **A**.
2. Visit the root of that subtree, **−**.
3. Visit its right subtree, **B**. The left subtree of `+` is now exhausted.
4. Visit **+**.
5. Go to the right subtree of `+`, rooted at `*`. Go left to **C** and visit it.
6. Visit **\***.
7. Go to the right subtree of `*`, rooted at `/`. Visit its left child **E**, then **/**, then **F**.

```math
\text{In-order: } A - B + C * E / F
```

**Pre-order traversal, step by step:**
1. Visit the root **+**.
2. Go to the left subtree: visit **−**, then **A** (both its subtrees are NULL), then **B**.
3. Go to the right subtree: visit **\***, then **C**.
4. Go to the right subtree of `*`: visit **/**, then **E**, then **F**.

```math
\text{Pre-order: } + \ -\ A\ B\ *\ C\ /\ E\ F
```

**Post-order traversal** (left, right, root):
1. Left subtree of `+`: **A**, **B**, **−**.
2. Right subtree of `+`: **C**, then the subtree at `/` gives **E**, **F**, **/**. Then visit **\***.
3. Finally visit the root **+**.

```math
\text{Post-order: } A\ B\ -\ C\ E\ F\ /\ *\ +
```

(The transcript said "A" at the end of the in-order and pre-order walks. That is an ASR error. The leaf is **F**.)

**Q&A: do precedence rules apply in the tree?**
- Yes. Precedence is **already built into the tree's hierarchy**.
  - Higher-precedence operations (here `/`) sit **lower** in the tree because they must be evaluated first.
- That is why **no brackets are needed** when reading the expression off the tree.

**Q&A: can you get the prefix form by converting the in-order (infix) string directly?**
- Yes, but you must respect **precedence and associativity**.
- Applied to $`A - B + C * E / F`$:
  1. Convert $`E / F`$ to $`/EF`$.
  2. Convert $`C * (/EF)`$ to $`*C/EF`$.
  3. Convert $`A - B`$ to $`-AB`$.
  4. Combine with `+` to get $`+\,-AB\,*C/EF`$. This matches the pre-order.
- **Associativity rules mentioned:**
  - `+` and `−` have the same precedence and are evaluated **left to right**.
    - Example: $`A + B - C`$ becomes $`(A+B) - C`$, whose prefix is $`-\,+\,A\,B\,C`$.
  - Exponentiation is evaluated **right to left**.
    - Example: $`a^{b^{c}}`$ is evaluated as $`a^{(b^{c})}`$, so $`b^{c}`$ is computed first.
- When operators have the same precedence, the order (left-to-right vs right-to-left) matters.

### 2.5 Reconstructing a Binary Tree from Traversal Sequences

**Key facts:**
- **One sequence alone is not enough.**
  - Post-order tells you the root (the **last** element). Pre-order tells you the root (the **first** element).
  - Neither tells you where the left subtree ends and the right subtree begins.
- **In-order gives the split.** Its structure is (left subtree, root, right subtree). Once the root is known:
  - everything to its left in the in-order sequence is in the left subtree;
  - everything to its right is in the right subtree.
- **Valid combinations:**
  - **Pre-order + In-order**
  - **Post-order + In-order**
- (Pre-order + post-order does not provide the left/right split.)

**Algorithm (numbered steps):**
1. Take the root from pre-order (its **first** element) or from post-order (its **last** element).
2. Find that root in the in-order sequence.
3. In-order elements to its left form the left subtree. Elements to its right form the right subtree.
4. Take the matching contiguous blocks of the pre-order or post-order sequence for each subtree.
5. Recurse on each subtree. A single node becomes a leaf directly.

**Worked Example 1 (pre-order + in-order, the expression tree):**
- Pre-order: `+ − A B * C / E F`
- In-order: `A − B + C * E / F`

Steps:
1. The first pre-order symbol is **+**, so + is the root.
   - In-order left of `+` is {A, −, B}, which forms the left subtree.
   - In-order right of `+` is {C, \*, E, /, F}, which forms the right subtree.
2. Left subtree: its pre-order block is `− A B`, so the root is **−**.
   - In the in-order, A is left of `−` and B is right of it. Both are single nodes, so they become leaves.
3. Right subtree: its pre-order block is `* C / E F`, so the root is **\***.
   - In the in-order, C is left of `*`, so C is a single-node left child.
   - {E, /, F} is right of `*`.
4. In {E, /, F}, the pre-order block is `/ E F`, so the root is **/**. E becomes its left child and F its right child.

This reproduces the original expression tree.

**Worked Example 2 (post-order + in-order):**
- In-order: `4 8 2 5 1 6 3 7`
- Post-order: `8 4 5 2 6 7 3 1`

Steps:
1. The last post-order element is **1**, so 1 is the root.
   - In-order left of 1 is {4, 8, 2, 5}.
   - In-order right of 1 is {6, 3, 7}.
2. Right subtree: its post-order block is `6 7 3`, and the last element is **3**, so 3 is the root.
   - In-order left of 3 is {6} and right of 3 is {7}. Both are single nodes.
   - So 6 is the left child of 3 and 7 is the right child.
3. Left subtree: its post-order block is `8 4 5 2`, and the last element is **2**, so 2 is the root.
   - In-order left of 2 is {4, 8} and right of 2 is {5}.
   - 5 is a single node, so it is the right child of 2.
4. For {4, 8}: the post-order block is `8 4`, so **4** is the root.
   - In the in-order (`4 8`), nothing is left of 4, so 4's left child is NULL.
   - 8 is to the right of 4, so 8 is the **right child** of 4.

**Final tree (in words):**
- The root is 1.
- 1's left child is 2.
  - 2's left child is 4, which has no left child and has right child 8.
  - 2's right child is 5.
- 1's right child is 3, with left child 6 and right child 7.

```
            1
          /   \
         2     3
        / \   / \
       4   5 6   7
        \
         8
```

*Check:* the in-order of this tree is 4 8 2 5 1 6 3 7 ✔ and the post-order is 8 4 5 2 6 7 3 1 ✔.

(The transcript first read the in-order as "4 8 5 1 6 3 7". The missing **2** is confirmed later in the lecture.)

### 2.6 Classifying Expression Trees (link to the previous lecture's definitions)

- The tree from Example 2 is simply a **binary tree**.
- The main expression tree is **strictly binary**.
  - Every internal (operator) node has exactly **two children**.
  - It is **not complete** and **not almost complete**, because the last level is not filled from the left.
- **Is every expression tree strictly binary?** Yes, because every binary operator has exactly two operands. (This assumes only binary operators.)
- **Can an expression tree be complete?** Yes, sometimes, but not always.
- **Can it be almost complete?** Yes.
  - Example given: a root operator whose left child is `+` (with children P and Q) and whose right child is the operand D.
  - The last level (P, Q) is filled from the left, so the tree is **almost complete and strictly binary**, but not complete.

### Quick Formula Sheet

- Left child (1-based): $`\text{LC}(i) = 2i`$
- Right child (1-based): $`\text{RC}(i) = 2i + 1`$
- Parent (1-based): $`\text{Parent}(i) = \lfloor i/2 \rfloor`$
- 0-based equivalents *(supplementary)*: $`2i+1`$, $`2i+2`$, $`\lfloor (i-1)/2 \rfloor`$
- Array size needed for height $`h`$ (levels): $`2^{h} - 1`$
- Root location: first element of pre-order, last element of post-order
- In-order split: $`\underbrace{\dots}_{T_L}\ R\ \underbrace{\dots}_{T_R}`$
