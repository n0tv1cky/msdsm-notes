FV: ONLY WHEN EVERYTHING IS CONSTANT

  • FV(rate, nper, pmt, [pv], [type]), found under Formulas → Function Library → Financial.
  • Use it only if payment, rate and periodicity are all constant.
  • Rate is per period: 13%/12 for monthly, /4 for quarterly.
  • type 1 = beginning of period; 0 or omitted = end. Leaving it out gives the wrong SIP answer.
  • Sign convention: cash out is negative, so FV comes back negative. Put a minus on pmt or in front of FV: =FV(13%/12, 12, -20000, 0, 1).

MANUAL SIP: 12 INDEPENDENT DEPOSITS

  • Each deposit is its own investment. Tenures are 12, 11, …, 1 months.
  • Month: type Jan, then drag the fill handle. SIP: 20,000. Monthly rate: =$B$3/12.
  • Value: =B6*(1+C6)^D6 (or POWER). Total: =SUM(E6:E17), which equals FV.
  • % contribution: =E6/$E$18, since every row divides by the same locked total.
  • Cell addresses are illustrative. Only the $ pattern matters.

LARGE DATA: LOAD AND TIDY

  • Click A1 first, because data loads from the selected cell. Then Data → Get Data → From File → From Text/CSV → Load.
  • The data arrives as an Excel Table (a Table Design tab appears). Undo that with Table Design → Tools → Convert to Range.
  • Add a filter first: Data → Filter, or Ctrl+Shift+L.
  • View → Freeze Panes → Freeze Top Row. Freezing works from the top or left edge only, never on a block in the middle.

NAME THE COLUMN, THEN COUNT / SUM

  • Click the first data cell, press Ctrl+Shift+↓, type Orders in the Name Box, then Enter.
  • =COUNT(Orders) counts numbers only. Text IDs need =COUNTA(Orders) (standard Excel, not shown in class).
  • =SUM(Total_Price). The exact name wasn't clearly heard.
  • With a named range you never reselect the data, and the name works later in lookups.

Choosing and building the right chart

Start from the question, then pick the chart, then lay the data out the way Excel needs it for that chart. Select → Insert alone never gets there.

PARENT / CHILD (S1, S2)

raw data in one column
Data → Text to Columns → Delimited → Other: | (spoken as "capital I"; pipe inferred). Fixed width cut "Samsung" in half.
biggest parent AND biggest brand?
Treemap or Sunburst (or a decomposition tree). Columns must be in the order Parent | Child | Value. Then Insert → Hierarchy → Treemap; Format Data Series → Label Options → Banner; Data Labels → tick Value.
only ONE category has children?
Pie of Pie. Split Series By: Position counts from the bottom, so cut the child rows to the bottom and set Values in second plot = 3 (the last 3 rows). Rename "Other" to the parent's name. Tick Percentage, untick Value.
several brands have children?
Pie of Pie can't do this. Go back to the treemap or sunburst.
plain bar / column
Shows one level only (parents or brands), so it fails this question.

TRENDS & TARGETS (S2, S3)

actual vs forecast?
Line chart. Cut 2017 into its own column, "Forecasted Sales". Copy the junction value 34,000 into both columns so the two lines meet. Set the forecast series' Dash type to dotted. Remove the repeated year labels.
target vs actual?
Bullet chart, built as a combo because Excel has no built-in one. Target: primary axis, low gap width (a wide bar). Actual: secondary axis, high gap width (a thin bar inside it). Change the secondary max from 4.5 to 5, then delete the secondary axis.
… and vs the average? (S3)
Add a third column: =AVERAGE(…) with $, dragged down. Change Series Chart Type → Combo → Average to Scatter; its markers form the line. Keep both axes identical.

IN-CELL & GRIDS (S2, S3)

many trends on one page?
Sparklines: Insert → Sparklines → Line / Column / Win-Loss. Data Range B2:J6 (inferred). Location Range has one cell per data row. Win/Loss needs a +1/0/−1 helper: =IF(C2>B2,1,IF(C2<B2,-1,0)) or =SIGN(C2-B2).
day × hour intensity?
Color Scales heat map. Apply it to the main grid only, then to each totals block separately. Hide the numbers with ;;; (sections: positive;negative;zero;text). For the legend, colour a 1…6 row with the same scale and hide it too.
status inside a cell?
=IF(C3>C2,1,IF(C3<C2,-1,0)) + 3-icon set + Show Icon Only. To find the rule: Manage Rules → This Worksheet. Default thresholds: green ≥ 67%, yellow ≥ 33% of range.
Arrows: =IF(C3>C2,$G$1,IF(C3<C2,$H$1,$I$1)), with absolute refs to the symbol cells.
Bars: =REPT("|",C2/10000) drops decimals, so 34,000 → 3 bars.

Choosing the chart:

  • "Select → Insert will never work on my questions" (S2). First work out which chart fits, then how Excel needs the data laid out.
  • "If you have to study the chart, it's a bad chart" (S2). A basic chart pointed at Rajasthan; the bullet chart shows West Bengal at a glance.
  • A chart that looks the same but has different numbers is a different chart (S2). A Pie of Pie attempt resembled the target but didn't match it, so always check the numbers.
  • Many charts are technically correct. Pick the one that is easiest to read and communicate (S2). In S1, bar/column attempts at the smartphone question showed parents or brands, never both.

Colours and axes:

  • Number of columns = number of colours (S2, repeated S3, S10 recap). Want five colours? Lay the data out in five columns. That's why the forecast gets its own column and the bullet chart gets a third Average column.
  • S10 quiz review: Q1's colour chart was won or lost on the IF helper table. Get the columns right and the colours follow.
  • "Two axes must share the same scale" (S2, S3). The defaults were 5 vs 4.5, which made actuals look below target when they weren't.
  • Moving axis bounds can make a small change look dramatic, or a big one flat (S2). The class demo used 50,000 as a value that was "too much".
  • Smoothed lines look nice, and he uses them for looks, but analytically they're "not a right idea" (S2).

Honest data and in-cell charts:

  • Missing October (S2): connecting September to November invents a slope nobody measured. Markers show which points really exist. A 0 instead fakes a crash.
  • Don't mix rectangles in a heat map (S3). The totals are far larger and would swamp the grid's colours. Don't colour by hand; let conditional formatting do it.
  • Sparklines are the tiny stock-trend lines in newspapers. Win/Loss is the green/red strip on intraday-trading sites (S3).

RANDOM AND SEQUENCE (S03)

  • =RANDBETWEEN(1,36): a random integer from bottom to top. Used in class to pick a random student; it showed 31 (the transcript also says 30).
  • =RANDARRAY(rows, cols, min, max, whole), e.g. (5,1,1,100,TRUE) gives 5 whole numbers from 1 to 100.
  • =RAND(): no inputs, returns 0 ≤ x < 1. Multiplying by 10 scales it: 0.87379 × 10 = 8.7379.
  • =SEQUENCE(rows, cols, start, step): (20,1,0,5) gives 0, 5, 10, 15, …
  • Spill: the formula lives only in the top-left cell. A lower cell shows no formula in the bar, which is how you spot an array function.
  • F9 (Fn+F9 on some laptops) recalculates. Random functions are volatile, so freeze them with Paste Special → Values.

CHOOSE, DATES, ROW / COLUMN (S03–S04)

  • CHOOSE(index, v1, v2, …) returns the index-th value. Use it for a fixed, indexed list instead of a long nested IF.
  • Random groups A–F: =RANDBETWEEN(1,6), freeze the values, then =CHOOSE(B2,"A","B","C","D","E","F") (B2 inferred).
  • WEEKDAY(date) returns 1–7 with Sunday = 1. =CHOOSE(WEEKDAY(A1),"Sunday",…,"Saturday"), or =TEXT(A1,"dddd"). Cell formatting only displays a name; it does not return one as a value.
  • =TODAY() gives today's date; =TODAY()+5 gives the date 5 days later.
  • ROW(), COLUMN(): the cell's own row or column number, useful for automation.
  • Array constants separate elements with commas: {1,2,3}.

The RANK trap (S03):

  • "This is like exam where many people get zero, complete zero." Ray Sanjog said this about answering #N/A for the rank of 28.
  • 28 is a valid mark on the 0–50 scale, so it must have a rank, even though nobody scored it. Add it with the union reference (marks,D10).

Circular references (S03):

  • They are "for knowledge only" and not used a lot. The point is to recognise the pop-up and know where to switch on iteration.
  • Caveat from the notes (not discussed in class): with CP = 110 the model can oscillate.
    • A discount of 12 makes profit −2, so no discount is given.
    • Profit is then 10, so the discount applies again, and the loop repeats.
    • The iterated result depends on the iteration count, so check it.

The unique-numbers puzzle (S03):

  • "Solve it with logic, not Google." No new function was needed; the hint was to combine SEQUENCE and RAND.
  • Random is not unique: RANDARRAY(10,1,1,10,TRUE) in class gave 10 three times and 7 twice.
  • A student answered with =SORTBY(SEQUENCE(10),RANDARRAY(10)). Ray Sanjog said he couldn't follow the logic but agreed the output was right. Why it works:
    • SEQUENCE(10) lists 1…10, each exactly once.
    • RANDARRAY(10) gives each of them a random decimal key.
    • SORTBY reorders the list by those keys. Reordering can move numbers but can never copy or drop one, so the result is a shuffle.
    • This is the same idea as RAND + RANK.EQ, done in one cell.

Choosing the function (S04):

  • A nested IF where CHOOSE fits still earns credit but may cost about 1 mark. "Knowing when to use which function is the real skill."
  • A live RANDBETWEEN recalculates on every click or edit, so your groups keep changing. Freeze it with Paste Special → Values.
  • S04's "+ three" offset on WEEKDAY is unclear in the recording. With the default numbering (Sunday = 1) and a list that starts at "Sunday", no offset is needed.

CONDITIONAL SUMS & COUNTS (S5)

SUMIF(range, criteria, sum_range)
One condition. =SUMIF(Name,J3,Dollars), dragged down. J3 is relative; named ranges stay fixed, so no $ is needed.
SUMIFS(sum_range, range1, crit1, …)
sum_range FIRST, then range/criteria pairs in any order. Units first or Name first gives the same answer.
COUNTIF / COUNTIFS
Count with one / several conditions. Negative units: =COUNTIF(Units,"<0").
named ranges
Dollars Units Name, typed in the Name Box. Unique salesperson list: copy Name → Data → Remove Duplicates.

CRITERIA AGAINST A CELL

">L10" → 0
Literal text: Excel can't read a cell address inside the quotes.
">"&L10
Operator in quotes, joined to the cell. =COUNTIF(Units,">"&L10) with L10 = AVERAGE(Units) (cell inferred).
& concatenates
"xx"&"yy" = "xxyy". CONCAT is an alternative.
typed average
Not accepted even if the count is right. The answer must update when the data changes.
#VALUE!
All ranges in SUMIFS / COUNTIFS must be the same size. Evaluate Formula shows the mismatch.

INDEX + MATCH (S6)

MATCH(value, array, 0)
Returns a position. 0 = exact match, "very critical". 30 lakh sits at position 6 of Salary.
INDEX(array, row, [col])
Returns the value at that position. Leave col out for a one-column named range.
INDEX(Name, MATCH(G2, Salary, 0))
Standard nesting. Swap in Country to get the country. Test it with an input above 3 crore (300 lakh).
INDEX(block, MATCH(…), {1,3})
Point it at the whole block; {1,3} spills two columns. On the one-column Name range it fails: there is no column 3.
same start row
Every named range must start on the same row (row 2), headers in all or none. Otherwise MATCH's position misaligns with INDEX's row.

Designing lookup tables: VLOOKUP, HLOOKUP, XLOOKUP, SUMPRODUCT

      
A lookup only works if you design its table to fit the function's assumptions. When a function's restriction blocks you, switch to another function rather than typing in the answer.

    


    

      

        
FOUR ASSUMPTIONS (VLOOKUP / HLOOKUP)

        
    
          
  • A lookup table exists. Usually you build it yourself: nobody hands you the table.
    • 
          
  • The key is in the leftmost column (the top row for HLOOKUP). If the key sits in column 2 and you select the whole table, it fails.
    • 
          
  • Approximate match needs an ASCENDING sort on the key column.
    • 
          
  • The index counts from the key column. The key is column 1, so you return from column 2 onwards. A third "extra bonus" column would be 3.
    • 
        

      

      

        
SYNTAX + RANGE_LOOKUP

        

          
VLOOKUP(value, table, col_index, [range_lookup])
HLOOKUP takes the same arguments, with a row index.

          
FALSE / 0 → exact match
Required for text keys such as T1 or P1. A "nearest" text key makes no sense.

          
TRUE / 1 / omitted → approximate
Returns the largest key ≤ value (the next smaller key). Needs ascending keys. Use it for numeric slabs.

          
TRUE on a text key
It "might happen" to give the right answer, but it is technically wrong.

        

      

      

        
LOCK, COPY, PATCH THE TABLE

        

          
named range: V_Bonus, H_Bonus
A name always points to the same cells, so you need no $ when dragging. Create it in the Name Box or Formulas → Define Name.

          
$D$2:$E$5 via F4
A selected range must be locked before you drag, or it shifts (range inferred). Named range and $ both work.

          
Paste Special → Transpose
Turns the horizontal H_Bonus into its vertical copy, V_Bonus.

          
below the first slab
Add a 0 → 0 row. The named range expands, you need no IF, and the formula stays untouched. Alternative: =IFERROR(VLOOKUP(B2,V_Bonus,2,TRUE),0).

SUMPRODUCT(a, b, …)
= Σ aᵢ·bᵢ. The arrays must be the same size. You can pass more than two.

          
=SUMPRODUCT($C$2:$F$2, C3:F3)

helper columns
Applied =IF(Qty>=Threshold, Disc%, 0) · Before = Qty × Price · Discount = Before × Applied · Paid = Before − Discount

PMT(rate, nper, pv, [fv], [type])

        

          
rate
rate per period: annual / 12

          
nper
years × 12

          
pv · fv
pv = loan amount · fv = 0 or omitted to pay it off fully

          
type

sign

the maths
