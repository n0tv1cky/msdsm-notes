## 1. Overview

This session moved from the one-dimensional retrieval functions covered last time (`MATCH`, `INDEX`, which work on a single row or column) to **two-dimensional table lookups**. Think of a telephone directory: give it a number and it returns the name. The instructor's main point was that you must know the assumptions behind `VLOOKUP` and `HLOOKUP` before using them:

- The search happens in the leftmost column (or top row).
- For approximate match, that column must be sorted ascending.
- Use exact match (`FALSE`) when the lookup keys are text.

He also stressed that **designing the lookup table is the real skill**, because in practice and in the exam you will usually have to build the table yourself.

The worked exercises were:

- A sales-bonus slab table, done both as vertical and horizontal tables using named ranges.
- Fixing the #N/A for small sales by redesigning the table.
- A wage/payment model using `SUMPRODUCT` + `VLOOKUP` with `FALSE`.
- A product-discount model broken into helper columns, using an array constant `{2,3,4}` to retrieve three columns at once.
- A commission-rate model choosing between two tables (robust vs. compact formula).
- An "upper slab" bonus problem that `VLOOKUP` cannot handle but `XLOOKUP` (match mode 1) can, with `IFERROR`/`MAX` to handle values above the top slab.

The session ended with quiz logistics. The next session covers What-If analysis.

## 2. Topics Covered (in order taught)

### 2.1 Recap and framing
- Yesterday: `MATCH`, `INDEX` and related functions. These are **retrieval functions on a 1-D array** (one row or one column).
- Today: **retrieval from a table** with `VLOOKUP` and `HLOOKUP`.
  - Analogy: a telephone directory, where you look up a number and retrieve the name.
- Rule of thumb from the instructor:
  - Use `MATCH`/`INDEX` for arrays.
  - Use `VLOOKUP`/`HLOOKUP` for tables.
  - Use `XLOOKUP`/`XMATCH` as the newer, more powerful alternatives.
  - The skill being tested is choosing the right function for the scenario.

### 2.2 Assumptions of VLOOKUP / HLOOKUP (must know)

1. **There must be a lookup table.** In real life and in the exam, nobody hands you the table; you have to build it.
2. **The search column must be the leftmost column** of the selected table array (or the **top row** for `HLOOKUP`).
   - If the search key is in column 2 and you select the whole table, it will not work.
3. **For approximate (nearest) match, the search column must be sorted in ascending order.**
   - ⚠️ Later in the lecture the instructor said "sorted and descending". That is a slip of the tongue. The correct requirement is ascending, as he stated first.
4. **Column index (VLOOKUP) / row index (HLOOKUP)** says which column/row to return. It counts from the first column of the table array.
   - The search column itself is column 1, so you always retrieve from column 2 onwards.
   - In a 2-column table you use `2`. If there were a third column (e.g., "extra bonus"), you would use `3`.

**Syntax**
```excel
=VLOOKUP(lookup_value, table_array, col_index_num, [range_lookup])
=HLOOKUP(lookup_value, table_array, row_index_num, [range_lookup])
```
- `range_lookup = FALSE` (or 0) gives an **exact match**.
- `range_lookup = TRUE` (or 1), or omitted, gives an **approximate/nearest match**. It returns the largest key ≤ lookup value and needs ascending sort.

### 2.3 Worked example 1: Sales bonus slab table (VLOOKUP and HLOOKUP)

**Business problem:** a salesperson's bonus depends on which sales slab their sales fall into. Example from class: sales of ₹2,000 gives a bonus of 100.

**Table layout.** ⚠️ The full table was not read out. The values below are inferred from the answers quoted in class (2,000→100; 2,700→100; 4,300→300 under "upper slab"; values above 5,000→300; 500 initially gives an error):

| Sales target (search key) | Bonus |
|---|---|
| 1,000 | 50 |
| 2,000 | 100 |
| ~3,000–4,000 ⚠️ | 200 |
| 5,000 | 300 |

**Steps**
1. The original table was **horizontal** (targets in the top row, bonus in the second row).
2. Copy it, then **Paste Special → Transpose** to create a **vertical** copy.
3. Name both ranges using the Name Box or Formulas → Define Name:
   - Vertical table: `V_Bonus` (said as "V bonus")
   - Horizontal table: `H_Bonus` (said as "H bonus")
   - ⚠️ Excel names can't contain spaces, so the exact spelling was probably `VBonus`/`V_Bonus`.
4. Using the **fx (Insert Function) dialog**, write the VLOOKUP:
   ```excel
   =VLOOKUP(B2, V_Bonus, 2, TRUE)
   ```
   - ⚠️ `B2` stands for the cell holding the sales value (actual address not stated).
   - Approximate match (`TRUE`, or omit the argument) is used because sales can be any value between slabs.
5. HLOOKUP version (students wrote this, then the instructor confirmed). Only the table changes, and the index is now a **row** index:
   ```excel
   =HLOOKUP(B2, H_Bonus, 2, TRUE)
   ```

**Named range vs. absolute reference (student question)**
- If you select the cell range directly, you must lock it with **F4** (`$`) before dragging the formula down. Otherwise the range shifts and gives wrong answers:
  ```excel
  =VLOOKUP(B2, $D$2:$E$5, 2, TRUE)   ' ⚠️ range inferred
  ```
- If you use a **named range**, you don't need `$`, because the name always refers to the same cells.
- Either method is fine.

### 2.4 In-class challenge: sales of 500 gives an error

- **Problem:** with sales = 500, the formula returns **#N/A**, because 500 is smaller than the smallest key (1,000). The person should get bonus = 0.
- **Constraint:** solve it **without writing an IF formula** and without touching the lookup formula.
- **Solution: change the lookup table.**
  - Insert a new first row/column: **Sales 0 → Bonus 0**.
  - The named range expands automatically, and any sales from 0 up to the first slab now returns 0.
- **Alternative (mentioned):** wrap the formula in `IFERROR`.
  ```excel
  =IFERROR(VLOOKUP(B2, V_Bonus, 2, TRUE), 0)
  ```
- **Large values are fine:** sales = 7,000 returns 300, since the last slab catches everything above it.
- **Key message:** lookup table design is the main skill.

### 2.5 SUMPRODUCT

- **Definition:** multiplies corresponding elements of equal-sized arrays, then adds the products:
  $$\text{SUMPRODUCT}(A,B) = \sum_{i=1}^{n} a_i\, b_i$$
- **Condition:** all arrays must have the **same size**.
- More than two arrays can be passed.
- Syntax:
  ```excel
  =SUMPRODUCT(array1, array2, ...)
  ```
- **Small demo:** the instructor typed some random numbers (heard as 6, 11, 9, 10, 14) into two columns and applied `=SUMPRODUCT(A1:A3, B1:B3)`. ⚠️ The exact layout wasn't audible.

### 2.6 Worked example 2 (Question 2): Total payment to workers

**Business problem:** find the total payment due to Mr. A/T(?), Mr. X and Mr. Y. ⚠️ The names were garbled.
- Each worker has a **category** (e.g., `T1`, `T2`, …).
- A wage table gives the payment rate for each category.
- If you change a worker's category, the rate and the payment should update automatically.

**Layout**
- **Inputs:**
  - Hours worked per worker, by type.
  - Multipliers/weights per type.
  - Each worker's category.
  - A wage-rate table (Category → Rate), named **`Wage`**.
- **Outputs:** Total Hours, Rate, Total Payment for each worker.

**Step 1: Total hours (weighted) with SUMPRODUCT.** The example calculation read out (⚠️ numbers from ASR):
$$1\times 0.5 + 1\times 1 + 20\times 1.25 + 5\times 1.15 = 0.5 + 1 + 25 + 5.75 = 32.25$$

```excel
=SUMPRODUCT($C$2:$F$2, C3:F3)
```
- ⚠️ The ranges are inferred.
- The instructor pressed **F4** on the array that must stay fixed (the multipliers) because the formula is dragged down to the other workers.

**Step 2: Rate.**
```excel
=VLOOKUP(B3, Wage, 2, FALSE)
```
- `B3` is the worker's category cell (the ASR heard "T3 B3").
- **`FALSE` is critical here.** The category (`T1`, …) is a **text string**, and "nearest match" makes no sense for text.
- `TRUE` might happen to give the right answer, but it won't always be correct.

**Step 3: Total payment.**
```excel
=G3*H3   ' Total Hours × Rate (cells inferred)
```

**Takeaway:** use lookup functions so that changing an input (the category) automatically updates the output, with no manual edits.

### 2.7 Worked example 3 (Question 3): Product discount, breaking a problem into parts

**Business problem:**
- Customers buy products (`P1`, `P2`, …).
- A discount is given **only if quantity purchased ≥ the product's threshold quantity**.
- Goal: compute the **amount paid** by each customer.

**Instructor's advice:** don't write one giant formula. Break the problem into helper columns.

**Lookup table (named `Product`):**

| Col 1: Product ID | Col 2: Unit Price | Col 3: Threshold Quantity | Col 4: Discount % |
|---|---|---|---|

**Worksheet layout (helper columns added):**

| Product | Qty Purchased | Unit Price | Threshold Qty | Discount % | Discount Applied | Amount Before Discount | Discount Amount | Amount Paid |
|---|---|---|---|---|---|---|---|---|

**Step 1: Retrieve all three values with ONE VLOOKUP using an array constant.** This curly-bracket technique was taught in the previous session.
```excel
=VLOOKUP(A2, Product, {2,3,4}, FALSE)
```
- ⚠️ `A2` is the product-ID cell (the ASR heard "P2").
- The result **spills** into three adjacent cells: unit price, threshold, discount %.
- **Exact match (`FALSE`)** is required because `P1`, `P2` are strings.
- It behaves like an array/spill formula, so the formula is visible only in the first cell.
- The order can be changed, e.g. `{2,4,3}` or `{4,3,2}`, to match the order of your output columns.
- If you're new to this, it's fine to write three separate VLOOKUPs (index 2, 3 and 4).
- The discount % column was formatted as **percentage, 2 decimals**.

**Step 2: Discount applied.**
```excel
=IF(B2>=D2, E2, 0)   ' IF Qty >= Threshold THEN Discount% ELSE 0
```
- In the class data, **only two customers qualified** for the discount.

**Step 3: Amount before discount.**
$$\text{Amount before discount} = \text{Quantity} \times \text{Unit price}$$
```excel
=B2*C2
```

**Step 4: Discount amount.**
$$\text{Discount amount} = \text{Amount before discount} \times \text{Discount applied}$$
```excel
=G2*F2
```

**Step 5: Amount paid.**
$$\text{Amount paid} = \text{Amount before discount} - \text{Discount amount}$$
```excel
=G2-H2
```

**Student Q&A on curly braces with HLOOKUP:**
- Yes, the same trick works with `HLOOKUP`.
- There, `{2,3,4}` are **row** indices, applied to the transposed (horizontal) table.

### 2.8 Worked example 4 (Question 4): Commission rate from two tables

**Business problem:**
- There are two commission-rate tables. One applies when a condition value is **less than 3**, the other when it is **3 or more**.
- ⚠️ The condition is likely years of experience/service; it wasn't stated clearly.
- The tables were named **`LT3`** ("less than three") and **`GT3`** ("greater than three").
- Compute the commission rate, then **Commission = Sales × Commission rate**.
- Range lookup should be **`TRUE`/approximate**, since the lookup is on numeric slabs. The instructor confirmed: "TRUE is good, it should be TRUE."

**Formula A: the IF chooses between two complete VLOOKUPs (more robust).**
```excel
=IF(C2<3, VLOOKUP(B2, LT3, 2, TRUE), VLOOKUP(B2, GT3, 2, TRUE))
```

**Formula B: the IF chooses the table inside one VLOOKUP (more compact).**
```excel
=VLOOKUP(B2, IF(C2<3, LT3, GT3), 2)
```
- The 4th argument is omitted, so it defaults to approximate match.
- ⚠️ `B2` = lookup value (e.g., sales), `C2` = the "< 3" condition cell. Both inferred.

**Which is better?**
- **Formula B** is shorter. But it **assumes the column to retrieve is in the same position (column 2) in both tables**.
- **Formula A** is **more robust**. If the return column differs between tables (column 2 in one, column 3 or 4 in the other), you just set a different index in each VLOOKUP.
- **Lesson:** think about robustness vs. compactness when choosing how to write a formula.

### 2.9 Worked example 5: "Upper slab" bonus, which VLOOKUP can't do (use XLOOKUP)

**Problem:**
- With the bonus table, sales of **2,700** normally returns **100** (the lower slab).
- New requirement: the person should get the **higher slab**, so 2,700 → **200**, and 4,300 → **300**.

**Why VLOOKUP fails:**
- Approximate VLOOKUP always returns the **next smaller** key. It cannot return the next larger one.
- A student (Rahan) pointed out that the problem is meant to be solved with **XLOOKUP**.
- Lesson: "Don't fix your mind on one formula; know each function's restrictions and pick the most suited one."

**XLOOKUP syntax**
```excel
=XLOOKUP(lookup_value, lookup_array, return_array, [if_not_found], [match_mode], [search_mode])
```
- `match_mode`:
  - `0` = exact (default)
  - `-1` = exact or next smaller
  - **`1` = exact or next larger**
  - `2` = wildcard
- In class, `if_not_found` and `search_mode` were left blank.

**Formula built in class**
```excel
=XLOOKUP(B2, $H$4:$H$9, $I$4:$I$9, , 1)
```
- ⚠️ A student mentioned `$H$4:$H$9` for the lookup array. The return-array range is inferred.
- Use absolute references (or named ranges) so the formula can be dragged.
- Results: 2,700 → 200 and 4,300 → 300.

**Problem at the top end:**
- **7,611** returns an error/0, because no slab is larger than the top threshold.
- First attempt: put `300` in `if_not_found`. The instructor rejected this because it **hardcodes** the value.

**Final fix: IFERROR plus MAX, no hardcoding.** Anything above the top slab gets the maximum bonus (300).
```excel
=IFERROR(XLOOKUP(B2, $H$4:$H$9, $I$4:$I$9, , 1), MAX($I$4:$I$9))
```
- So "if more than 5,000, show 300."
- The `IFERROR` must be put in the **first** cell and then dragged down. At first the instructor had added it to a different cell, and the #N/A remained.

*Side note (not covered in class):* `INDEX`/`MATCH` with `match_type = -1` on a **descending**-sorted table can also return the next-larger slab. In class, though, XLOOKUP was presented as the intended tool.
