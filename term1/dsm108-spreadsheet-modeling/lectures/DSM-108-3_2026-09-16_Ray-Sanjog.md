### 2.1 Recap: Bullet chart (finishing the Session 2 exercise)

**Business problem:** compare state-wise performance against an average (target) and see which states fall below it.

**Layout:** each state has two data series (two "lines"/columns). The principle from last class is that you need three columns for three lines. Add a **third column containing the average**.

```excel
=AVERAGE($B$2:$B$N)     ' average column; exact range not stated in the transcript (inferred)
```

Type it once and drag it down so every row has the same average value. The transcript only says "equal to this one" and then drag, so the exact reference is inferred.

**Steps:**
1. Select the data and insert a **clustered bar/column chart**.
2. Right-click the chart → **Change Series Chart Type** → **Combo**. All three series start as clustered.
3. Change the **third (average) series to Scatter**.
4. Put the other two series on the **secondary axis**.
5. **Important rule:** whenever you build a combo chart, make the primary and secondary axes the same (identical min/max). Otherwise the series are not comparable.
6. Format the scatter markers (Format → Marker) so the average shows as a line.
7. Optional: double-click a single data point to highlight it, for example color the problem state differently.

**Interpretation:** West Bengal is the only state below the average and is the worst performer. Himachal Pradesh is the best.

**Why the workaround:** a bullet chart is not built into Excel, which is why these tricks are needed. It is popular when you have a primary target and actual values (e.g., sales vs. target).

### 2.2 Sparklines (built-in in-cell charting)

**Concept:** instead of one large line chart, each row's trend is drawn inside a single cell. There is one output cell per row. The instructor contrasted this with earlier manual in-cell charting (conditional formatting, `REPT`, arrows).

**Data:** 5 rows of sales (months across the columns).

**Steps (Line sparkline):**
1. Choose 5 empty output cells next to the data, one per row. Highlighting them is optional.
2. **Insert → Sparklines → Line**.
3. **Data Range:** `B2:J6`. The ASR says "GB2 to J6", so B2:J6 is inferred.
4. **Location Range:** the 5 output cells. The number of cells must equal the number of data rows.
5. Press OK. The **Sparkline** contextual tab appears, where you can:
   - change the line weight;
   - mark the High Point, Low Point, etc.

**Column sparkline:** same steps, choosing **Insert → Sparklines → Column**.

**Win/Loss sparkline:**
- This chart is common on trading sites (e.g., intraday trading): green if positive, red if negative, for each period.
- It needs a **helper matrix** of $+1$, $0$, $-1$:
  - $+1$ if this month > previous month;
  - $-1$ if this month < previous month;
  - $0$ if they are equal.

```excel
=IF(C2>B2,1,IF(C2<B2,-1,0))      ' Feb vs Jan for row 2; drag right and down
```

  - Cell positions are inferred: data in B2:J6, so the helper starts comparing column C against column B.
  - An equivalent shortcut is `=SIGN(C2-B2)`. This was not shown in class.
- Then use **Insert → Sparklines → Win/Loss** on the helper matrix.

**Note:** Sparklines are an old feature (around 10–15 years). They are useful for showing many trends on one page, like the stock-price trend lines in newspapers.

### 2.3 Heat map with conditional formatting (Session 3 data: accidents)

**Business problem:** accident counts by **day of week × hour of day**. The goal is to see at a glance which times are dangerous or safe to go out. The raw table is hard to read.

**Steps:**
1. **Add totals.**
   - Sum each day's accidents.
   - Sum each hour's accidents across days (the instructor mentions "sum of number of accidents at 12…").
   - Example (ranges inferred):
     ```excel
     =SUM(B2:B25)    ' total per day/column; exact ranges inferred
     ```
   - From the totals alone, **Friday** is the most dangerous day.
2. **Apply a color scale.**
   - Select only the main data rectangle, not the totals.
   - **Home → Conditional Formatting → Color Scales**.
3. **Format the totals rectangles separately.**
   - Apply the color scale to each totals block on its own.
   - **Don't mix rectangles.** If the totals are included with the main grid, the coloring goes wrong because the totals are much larger.

**Reading the result:**
- Peaks are around **89** accidents at **9:00 a.m. Friday** and **3:00 p.m. Friday**.
- Dangerous hours: **8 a.m., 9 a.m., 12 p.m., 5 p.m., 6 p.m.**
- **Friday** is the most dangerous day. **Saturday and Sunday** are the safest.

**Trick: hide the numbers but keep them in the cells.**
1. Select the area whose numbers should not show.
2. Right-click → **Format Cells → Custom**.
3. Replace `General` with three semicolons:
   ```excel
   ;;;
   ```
4. The values still exist (formulas and colors still work) but are not displayed. Deleting the format makes them visible again.

**Why `;;;` works:**
- A custom number format has sections `positive;negative;zero;text`.
- Leaving all of them empty hides every value.
- The instructor noted that `;;` sometimes works too.

**Exercise: add a legend below the heat map.**
1. Type a row of incremental numbers, e.g., 1 2 3 4 5 6. Any increasing numbers work.
2. Apply the same color scale to them.
3. Hide them with `;;;`.
4. Label the ends (e.g., Low → High).
5. Add a black line with **Insert → Shapes → Line**.

**Advice:** don't color cells manually. Let conditional formatting do it, and always try to make the chart better.

### 2.4 Cell referencing: absolute, relative/mixed, circular

#### (a) Absolute reference (recap)

A `$` on both the column and the row (e.g., `$B$2`) keeps the address fixed when the formula is copied or dragged.

#### (b) Relative and mixed reference: multiplication table

**Task:** fill a $9 \times 9$ multiplication table using **exactly one formula**, typed once and then dragged right and down.

**Setup:**
1. Type 1, 2, …, 9 down column A, starting at A2.
2. Copy the list and use **Paste Special → Transpose** to put 1…9 across row 1, starting at B1. Transpose converts rows to columns and columns to rows.
3. Each cell must compute $(\text{row header}) \times (\text{column header})$.

**Why the naive formula fails:**
- Typing `=A2*B1` and dragging gives `=A3*B2`, `=B2*C1`, and so on.
- Both references shift, so the headers are lost.
- Use **Show Formulas** (Formulas tab, or Ctrl+\`) to see this.

**Correct formula (in B2):**

```excel
=$A2*B$1
```

- `$A2`: the column is locked to A (row headers) and the row changes.
- `B$1`: the row is locked to 1 (column headers) and the column changes.

For a cell in row $i$ and column $j$, the result is $A_i \times \text{Row1}_j$.

#### (c) Circular reference: discount/profit model

This was "for knowledge only" and is not used a lot.

**Inputs:**

| Item | Value |
|---|---|
| Cost Price (CP) | 100, later changed to 110 |
| Selling Price (SP) | 120 |
| Discount % | 10% |

**Calculated fields:**
- Discount amount $= SP \times \text{Discount\%}$
- Profit $= SP - CP - \text{Discount amount}$

**Check with CP = 100:**
- Discount amount $= 120 \times 0.10 = 12$.
- Profit $= 120 - 100 - 12 = 8$.

**Business rule:** a discount is given **only if profit > 0**. Cell positions below are inferred (CP in B1, SP in B2, Disc% in B3, Discount amount in B4, Profit in B5):

```excel
B4:  =IF(B5>0, B2*B3, 0)       ' Discount amount depends on Profit
B5:  =B2-B1-B4                 ' Profit depends on Discount amount
```

- Discount depends on Profit, and Profit depends on Discount. This is a **circular reference**, so Excel shows a warning pop-up. If you get the pop-up, you built it correctly.
- Leave out the "total profit %" column; only total profit was asked for.

**Formula auditing tools (Formulas tab):**
- **Trace Precedents**
- **Trace Dependents**
- **Remove Arrows**
- **Evaluate Formula** (Step In / Step Out)

**Fixing the circular reference:**
- Windows: **File → Options → Formulas → Enable iterative calculation**.
- Mac: **Excel → Preferences → Calculation**.

**Example with iteration on:**
- With CP changed to 110, the instructor's reading was that **no discount is given**, leaving a profit of $120 - 110 = 10$.
- Caveat (not discussed in class): this model can oscillate. A 12 discount gives profit $-2$, so no discount, so profit 10, so the discount applies again. The iteration result depends on the iteration count, so check the result carefully.

**Summary:** three kinds of referencing were covered: **absolute, relative (including mixed), and circular**.

### 2.5 Basic statistical functions with a named range

**Data:** a column of exam marks. Possible range 0–50; the highest score is 50 and the lowest is 0.

**Name the range first.**
1. Click the first mark, not the heading.
2. Press **Ctrl+Shift+↓** to select the column.
3. Type `marks` in the **Name Box** and press Enter.

Names make formulas much easier to write.

```excel
=MAX(marks)
=MIN(marks)          ' ASR says "mean"; could be MIN or AVERAGE — both shown
=AVERAGE(marks)
=MEDIAN(marks)
=MODE(marks)         ' or =MODE.SNGL(marks)
```

**Tip:** type the function name and an opening bracket, then click the **fx** button. The Function Arguments dialog shows each argument, such as Array and k.

```excel
=LARGE(marks,5)      ' 5th largest (k can point to a cell containing 5)
=LARGE(marks,2)      ' 2nd largest
=SMALL(marks,2)      ' 2nd lowest
```

#### RANK, and ranking a value not in the list

```excel
=RANK.EQ(31,marks,0)     ' or legacy =RANK(31,marks,0)
```

- **Order:** `0` or omitted means **descending** (highest mark = rank 1). Any non-zero value means ascending.
- The rank of a score of **31** is **14**.

```excel
=RANK.EQ(28,marks,0)     ' returns #N/A
```

- This gives **#N/A** because nobody actually scored 28.
- Answering "NA" is wrong: 28 is a possible score (0–50), so it should have a rank.

**Fix: add the value to the reference using a comma (union reference).**

```excel
=RANK.EQ(D10,(marks,D10),0)    ' D10 holds 28; the extra parentheses make a union of marks + D10
```

- The comma inside the parentheses appends an element to the reference, so 28 is now in the list and gets a valid rank.
- The cell **D10** comes from the transcript ("comma 28 d10"). Its exact position is inferred.

### 2.6 Random number and sequence functions

| Function | Syntax | What it does |
|---|---|---|
| `RANDBETWEEN` | `=RANDBETWEEN(1,36)` | Random integer between bottom and top. The example picked a random student; the transcript mentions 30, then 36, and showed 31. Recalculates on every refresh. |
| `RANDARRAY` | `=RANDARRAY(5,1,1,100,TRUE)` | Arguments are (rows, columns, min, max, whole_number). This gives 5 random integers 1–100 in one column. Newer function. |
| `RAND` | `=RAND()` | No inputs. Returns a decimal $0 \le x < 1$. Very old function. |
| `SEQUENCE` | `=SEQUENCE(20,1,0,5)` | Arguments are (rows, columns, start, step). This gives 0, 5, 10, 15, … The ASR "0 5 15 25" is an error. Modern function. |

- Press **F9** to recalculate (**Fn+F9** on some laptops) and the random values change.
- **Dynamic array / spill concept** (introduced for the first time here):
  - With `RANDARRAY` and `SEQUENCE`, only the **top-left cell** contains the formula.
  - The other cells are spilled results.
  - Clicking a lower cell shows no formula in the formula bar. This is how you tell it is an array function.

### 2.7 Logic puzzle: unique random numbers 1–10 for 10 people

**Task:**
- Each of 10 people gets a number from 1–10.
- The assignment must be **random**, so nobody can predict who gets what.
- **No repeats.**
- No new function is needed; solve it with logic, not Google.

**Why the obvious functions fail:**
- `RANDBETWEEN(1,10)` dragged down can repeat values.
- `=RANDARRAY(10,1,1,10,TRUE)` also repeats. In class, 10 appeared three times and 7 twice.

**Hint given:** combine `SEQUENCE` and `RAND`.

**Instructor's solution (rank random decimals):**

```excel
A2:A11:  =RAND()                 ' or =RANDARRAY(10) — 10 random decimals
         → Copy → Paste Special → Values   (freeze them so they don't change on refresh)
B2:      =RANK.EQ(A2,$A$2:$A$11)  ' drag down → a permutation of 1..10
```

- This works because the chance of two `RAND()` values being equal is extremely small. It is not impossible, but it is negligible.
- Cell ranges are inferred.

**Student solution that also works (one formula):**

```excel
=SORTBY(SEQUENCE(10),RANDARRAY(10))
```

- The instructor said he could not follow the logic but agreed the output was correct.
- How it works: `SEQUENCE(10)` gives 1…10. `RANDARRAY(10)` gives 10 random keys. `SORTBY` sorts 1…10 by those random keys. The result is a random shuffle of 1–10 with no repeats.

**Approach that does not guarantee uniqueness:**

```excel
=ROUND(RAND()*10,0)
```

- $\text{RAND}() \times 10$ scales the value to $[0,10)$. For example, $0.87379 \times 10 = 8.7379$.
- Rounding can produce duplicates and can produce 0, so it fails the 1–10 unique requirement.
