## 1. Overview

This session covered Excel's **What-If Analysis** toolkit, built around a simple **loan/EMI model**. The model has three inputs (loan amount, interest rate, tenure) and three outputs (EMI, total paid to bank, extra paid). The EMI is computed with `PMT`.

On top of this model the instructor demonstrated four tools:
- a **one-way data table**, once varying tenure and once varying interest rate;
- a **two-way data table**, also called a sensitivity table, varying interest rate × tenure;
- **Goal Seek**, used to find the tenure needed for a ₹50,000 EMI and the maximum loan affordable at that EMI;
- **Scenario Manager**, used to define best/worst/base scenarios and generate Summary and PivotTable reports.

Students then solved an exam-style **bike break-even problem** (fixed cost ₹4,45,000, variable cost ₹1,100, price ₹2,100). It used a one-way data table, a line chart, Goal Seek for break-even (445 bikes, and 636 bikes at a ₹1,800 price), and a two-way data table.

The instructor also explained:
- how he grades these questions: he checks the model first, then looks for the `{=TABLE()}` curly braces;
- the exam format: 45 minutes, one dataset, three questions.

The session closed with an optional, non-examinable demo of a **dynamic chart using `OFFSET`**.

## 2. Topics in Order

### 2.1 Building the Loan Model (template)

**Business problem:** You take a loan. How much is the monthly EMI, how much do you pay the bank in total, and how much of that is extra (interest)?

**Layout (inferred: labels in column A, values in column B):**

| Cell | Label | Value / Formula | Role |
|---|---|---|---|
| A1/B1 | Loan amount | `2000000` (₹20 lakh) | Input |
| A2/B2 | Interest rate | `10%` (format cell as Percentage first) | Input |
| A3/B3 | Tenure (years) | `10` | Input |
| A6/B6 | EMI | `=-PMT(B2/12,B3*12,B1)` | Output (**B6 confirmed**) |
| A7/B7 | Total paid to bank | `=B6*B3*12` | Output |
| A8/B8 | Extra paid | `=B7-B1` | Output (**B8 confirmed**) |

**Naming the cells (important):**
- Select the label and value columns, then go to **Formulas → Create from Selection** (left column) → OK.
- Confirm in **Name Manager** that all names exist.
- Why bother: names make formulas readable. More importantly, the **Scenario Manager report will show B1, B2, B3… instead of meaningful names** if you skip this step.

With names the formulas read like this (Create from Selection turns spaces into underscores):

```excel
=-PMT(Interest_rate/12, Tenure*12, Loan_amount)      ' EMI
=EMI*Tenure*12                                        ' Total paid to bank
=Total_paid_to_bank-Loan_amount                       ' Extra paid
```

**The `PMT` function**

`PMT` is a financial function. It applies only when both the **interest rate and the payment are constant** over the loan.

```excel
=PMT(rate, nper, pv, [fv], [type])
```

| Argument | Meaning in this model |
|---|---|
| `rate` | Rate **per period**: annual rate / 12, because payments are monthly |
| `nper` | Number of periods: years × 12 |
| `pv` | Present value, i.e., the loan amount |
| `fv` | Balance left at the end. Use 0 or omit to pay the loan off fully. Use a non-zero value only if some amount stays unpaid at the end of the tenure. |
| `type` | 0 or omitted = payment at **end** of period; 1 = **beginning** of period. **Changing this changes the answer.** |

The underlying math:

$$EMI = \frac{P \, r \, (1+r)^{n}}{(1+r)^{n} - 1}, \quad r = \frac{\text{annual rate}}{12}, \quad n = 12 \times \text{years}$$

**Points from the live demo:**
- **Sign convention:** `PMT` returns a **negative** number because it is cash going out. Excel shows negatives in red or in brackets depending on formatting. Put a **minus sign before `PMT`** to make it positive (this was covered in the first class).
- **Common mistake (made live):** forgetting to divide the rate by 12. This gave an absurd EMI of several lakh per month. The fix is `B2/12` and `B3*12`.
- The instructor briefly toggled `type` to 1 (beginning of period). It was not clearly stated which version was kept; the end-of-period default is assumed below.

**Results (end-of-period):**

| Scenario | EMI | Total paid | Extra paid |
|---|---|---|---|
| ₹20L, 10%, 10 yrs | ≈ ₹26,430 | ≈ ₹31.7 lakh | ≈ ₹11.7 lakh ("paying 11 lakh extra") |
| ₹20L, 10%, 20 yrs | ≈ ₹19,300 | ≈ ₹46.3 lakh | ≈ ₹26.3 lakh (instructor said "~25 lakh") |

*(With `type`=1 at 10 years, the EMI would be ≈ ₹26,212.)*

**Takeaway:** "Pay your loan off as early as possible." At 20 years and 10%, the extra paid exceeds the original loan amount.

**Why What-If analysis matters:** It is used for scenario-based planning, i.e., seeing how outputs change when inputs change. It is most popular in **finance, project selection, and project management**. It is a very old Excel feature, which is part of why it is so widely used.

### 2.2 One-Way Data Table #1 — Varying Tenure

**Goal:** See EMI, Total paid, and Extra paid for different tenures, holding loan amount (₹20L) and rate (10%) fixed.

**Layout (location on sheet inferred, e.g., starting at D2):**

```
            D            E          F              G
2      (headings: Tenure | EMI | Total paid | Extra paid)   <- text, DO NOT select
3      [blank]       =EMI       =Total_paid_to_bank  =Extra_paid   <- formula row
4      8
5      10
6      12
7      15
8      18
9      20
```

The formula row simply links to the model outputs:

```excel
E3: =B6      (or =EMI)
F3: =B7
G3: =B8
```

**Format rules (fixed by Excel):**
- The varying input values go **down a column, on the left**.
- The formula row sits **one row above the first input value and one column to the right**.
- You can put several output formulas across this top row. A one-way table can show multiple outputs.

**Steps:**
1. Select **only the values block plus the formula row**, e.g., `D3:G9`. **Do not select the text headings.** If you do, Excel just repeats the text.
2. Go to **Data → What-If Analysis → Data Table**.
3. Leave **Row input cell** blank. Set **Column input cell** to `B3` (Tenure), because the varying values are in a column.
4. Click **OK**.

**Result:** Each result cell contains an array formula:

```excel
{=TABLE(,B3)}
```

**Exam relevance:** If you hover over a result cell and see the **curly brackets `{ }`**, the instructor knows you used the Data Table feature. If you typed formulas and dragged them down, there are no braces, and **that does not count as using a data table**.

**Expected results (≈ computed, 10%, ₹20L):**

| Tenure | EMI | Total paid | Extra paid |
|---|---|---|---|
| 8 | ≈ 30,348 | ≈ 29.13 L | ≈ 9.13 L |
| 10 | ≈ 26,430 | ≈ 31.72 L | ≈ 11.72 L |
| 12 | ≈ 23,902 | ≈ 34.42 L | ≈ 14.42 L |
| 15 | ≈ 21,492 | ≈ 38.69 L | ≈ 18.69 L |
| 18 | ≈ 19,997 | ≈ 43.19 L | ≈ 23.19 L |
| 20 | ≈ 19,300 | ≈ 46.32 L | ≈ 26.32 L |

It is called **one-way** because only **one input variable** changes.

### 2.4 Two-Way Data Table (Sensitivity Table)

**Goal:** Show EMI for every combination of interest rate × tenure. This is "the popular one." In finance it is often called a **sensitivity table**.

**Layout (inferred position):**

```
             I        J     K     L     M     N     O
2         =B6        8     10    12    15    18    20     <- tenures across the top (transposed)
3          8%        .     .     .     .     .     .
4         10%        .     .     .     .     .     .
5         12%        .     .     .     .     .     .
6         14%        .     .     .     .     .     .
7         15%        .     .     .     .     .     .
8         20%        .     .     .     .     .     .
```

- **Interest rates go down the left column.** Tenures go across the top row. The instructor copied the tenure list and pasted it using **Transpose**.
- The **corner cell** (top-left, where the row and column meet) holds the **single output formula**, e.g., `=B6` for EMI. You could put `=B8` (Extra paid) or `=B7` there instead. Only **one** output is possible.

**Steps:**
1. Select the whole block including the corner cell, the top row, and the left column (e.g., `I2:O8`).
2. Go to **Data → What-If Analysis → Data Table**.
3. Set **Row input cell = `B3`** (Tenure, because the values in the top row are tenures).
4. Set **Column input cell = `B2`** (Interest rate, because the values in the left column are rates).
5. Click **OK**. The result cells show `{=TABLE(B3,B2)}`.
6. *(Optional, shown in class)* Apply **Conditional Formatting → Color Scale** so higher EMIs appear red.

**One-way vs two-way:**

| | One-way | Two-way |
|---|---|---|
| Inputs varied | 1 | 2 |
| Outputs shown | Several (one per column in the formula row) | **Only one** (in the corner cell) |
| Input cell(s) | Row *or* Column | Row *and* Column |

### 2.5 Side Issue: "Why do my data tables change?"

**Student Q:** When I ran Goal Seek (next section), the other tables changed. Why?

**A:** Data tables are **live**. They recalculate from the model every time any input changes.
- In the **tenure** table, changing the tenure input cell has no effect, because that table substitutes its own tenure values.
- In the **interest-rate** table, the tenure is taken from the model. Change the tenure and that table's values change.
- The **formula row** always shows the model's current output.

**Fixes:**
- **Copy → Paste Values** the table elsewhere if you need a frozen snapshot.
- Or use **Scenario Manager** if the goal is a static report.

### 2.6 Goal Seek

Goal Seek works **backwards**: it sets one output to a target value by changing **exactly one** input.

**Example A — What tenure gives an EMI of ₹50,000?** (Loan ₹20L, rate 10%)
1. Go to **Data → What-If Analysis → Goal Seek**.
2. **Set cell:** `B6` (EMI).
3. **To value:** `50000`.
4. **By changing cell:** `B3` (Tenure).
5. Click OK, and OK again to keep the result. *(The instructor had to redo it once because the result didn't stick.)*

**Answer:** Tenure ≈ **4.07 years**, about 4 years 1 month (≈ 48.9 months).

**Example B — Maximum loan for a ₹50,000 EMI?** First reset tenure to **10 years** at 10%.
- Goal Seek: Set `B6` to `50000` by changing `B1` (Loan amount).
- **Answer:** ≈ **₹37.8 lakh** ("around 38 lakh").
- The instructor expected roughly double the loan (₹40L). But EMI is linear in loan amount: $50{,}000 / 26{,}430 \approx 1.89\times$, and $1.89 \times 20\text{L} \approx 37.8\text{L}$.

### 2.7 Scenario Manager

**Purpose:** A **reporting tool**. Use it to present best/worst/base cases in a report or a PPT. It doesn't do any optimization ("there's no other objective").

**Steps:**
1. Go to **Data → What-If Analysis → Scenario Manager → Add**.
2. **Scenario name:** e.g., "Best scenario".
3. **Changing cells:** select all three input cells, `B1:B3`. Then click OK.
4. Enter the values for this scenario and click **Add** to create the next one.

**Scenarios created:**

| Scenario | Loan amount | Interest rate | Tenure | EMI (≈ computed) | Extra paid (≈ computed) |
|---|---|---|---|---|---|
| Best | 20,00,000 | 9% | 15 | ≈ 20,285 | ≈ 16.5 L |
| Worst | 25,00,000 | 15% | 10 | ≈ 40,333 | ≈ 23.4 L |
| Third (kept "same" as base) | 20,00,000 | 10% (inferred) | 10 (inferred) | ≈ 26,430 | ≈ 11.7 L |

*(Note: the "best" case has the lowest EMI but a higher total extra paid than the base, because the loan is spread over 15 years.)*

**Editing:** Select a scenario → **Edit** → change the values → OK.

**Generating the report:**
1. Click **Summary**.
2. **Report type:** choose **Scenario summary**, the simple formatted table, which Excel creates as a new sheet.
3. **Result cells:** choose the outputs to report. In class: **`B6, B8`** (EMI and Extra paid). You can pick any subset.
4. Click OK.
5. Repeat with **Scenario PivotTable report** to get the same data as a pivot table.

**This is where naming pays off.** The report shows `Loan_amount`, `Interest_rate`, and so on instead of `$B$1`, `$B$2`.

**Recap — the What-If features covered:**
1. One-way data table
2. Two-way data table
3. Goal Seek
4. Scenario Manager

### 2.8 Practice Problem (Exam-Style): Bike Break-Even

Students had about 10 minutes to solve all four parts. The problem has four questions, but the instructor noted the real exam has three questions on one dataset in 45 minutes.

**Business problem:** A bike maker has a fixed cost and a per-bike variable cost, and sells at a fixed price. **Simplifying assumption:** every bike built is sold. The instructor noted this can be made harder, e.g., bikes produced ≠ bikes sold.

**Model layout (inferred cells):**

| Cell | Label | Value / Formula |
|---|---|---|
| B1 | Fixed cost | `445000` |
| B2 | Variable cost (per bike) | `1100` |
| B3 | Selling price | `2100` |
| B4 | Bikes sold | `100` (arbitrary placeholder) |
| B6 | Revenue | `=B3*B4` |
| B7 | Expenses | `=B1+B2*B4` |
| B8 | Profit | `=B6-B7` |

The same formulas using named cells:

```excel
=Selling_price*Bikes_sold
=Fixed_cost+Variable_cost*Bikes_sold
=Revenue-Expenses
```

At 100 bikes: Revenue ₹2,10,000, Expenses ₹5,55,000, Profit **−₹3,45,000**.

**Q1 — Impact on revenue, expenses, and profit as bikes sold varies from 200 to 700 (one-way data table)**
- Put 200 in the input column and fill down in steps of 100 to 700.
- Formula row: `=B6`, `=B7`, `=B8`.
- Select the block → **Data Table** → **Column input cell = `B4`**.

| Bikes | Revenue | Expenses | Profit |
|---|---|---|---|
| 200 | 4,20,000 | 6,65,000 | −2,45,000 |
| 300 | 6,30,000 | 7,75,000 | −1,45,000 |
| 400 | 8,40,000 | 8,85,000 | −45,000 |
| 500 | 10,50,000 | 9,95,000 | 55,000 |
| 600 | 12,60,000 | 11,05,000 | 1,55,000 |
| 700 | 14,70,000 | 12,15,000 | 2,55,000 |

**Graphical check — line chart:**
1. Select the Revenue and Expenses columns of the table.
2. Go to **Insert → Line Chart**.
3. Use **Select Data → Edit** to rename "Series1/Series2" to Revenue and Expenses.

The lines cross at about **445 bikes**, which is the break-even point.

**Q2 — Break-even volume (Goal Seek)**
- Goal Seek: Set `B8` (Profit) to `0` by changing `B4` (Bikes sold). **Answer: 445 bikes.**
- Check by hand:

$$Q^{*} = \frac{FC}{P - VC} = \frac{445{,}000}{2{,}100 - 1{,}100} = 445$$

**Q3 — Break-even if the selling price drops to ₹1,800**
- Set `B3 = 1800`, then Goal Seek again: Profit → 0 by changing Bikes sold.
- **Answer: ≈ 636 bikes.**

$$Q^{*} = \frac{445{,}000}{1{,}800 - 1{,}100} \approx 635.7 \Rightarrow 636$$

- The chart also hinted "600-something."

**Q4 — Net income by price and units sold (two-way data table)**
1. **Reset the selling price to 2,100** first.
2. Corner cell: `=B8` (Profit).
3. Put **prices across the top row** and **bikes sold down the left column**. The specific price values weren't stated.
4. Go to **Data Table** → **Row input cell = `B3`** (Selling price), **Column input cell = `B4`** (Bikes sold).

Sanity checks mentioned: price 2,100 and 500 bikes gives ₹55,000. Price 2,100 and 635 bikes gives ₹1,90,000.

**Student Q:** After Goal Seek, the Bikes sold cell shows 635/636 instead of the original value. Does that break the tables?

**A:** No. The table values only *look* like they change; they are refreshed. Each table cell substitutes its own price and quantity, so whatever sits in `B4` doesn't matter. The table values change only if a non-varied input changes, such as **fixed cost or variable cost**.

Tools used in the practice: one-way table, Goal Seek, two-way table. Scenario Manager was not used here.

### 2.9 How the Instructor Grades These Questions

1. **Model first.** He changes an input (e.g., sets bikes sold to 700 or 500) and checks that profit computes correctly. "If the model is right, all of them will be right."
2. **Data table check.** He looks at the layout and for the **curly braces `{=TABLE(...)}`**. If those are present, the data table itself rarely has errors.
3. **Goal Seek** answers can't be verified as having used Goal Seek, but Goal Seek *is* the intended method.
4. **Scenario Manager:** he gives specific scenario values in the question and checks that your report's numbers match.
5. **Harder model twists to expect:** e.g., bikes produced ≠ bikes sold. You will need to think about how the equations change.

### 2.10 Optional / Not Examinable: Dynamic Chart with `OFFSET`

This follows up on a teaser from the last session.
- **Goal:** A chart that grows automatically when new data rows are added. Example: add year 2027 with sales of 100, and the chart updates on its own.
- One alternative is an Excel Table, which was not covered.
- **Approach:** Define a **named range** with `OFFSET`, then use that name as the chart series.

```excel
=OFFSET(reference, rows, cols, [height], [width])
```

Reconstructed definition; the exact anchor cell and the choice of `COUNT` vs `COUNTA` were inferred from "count… B colon B… columns one":

```excel
Name: Sales
Refers to: =OFFSET(Sheet1!$B$2, 0, 0, COUNT(Sheet1!$B:$B), 1)
```

- The `height` argument (the count of column B) grows as rows are added.
- `width = 1`, since there is only one column.
- In the chart's **Select Data → Edit series**, set the values to `=Sheet1!Sales` (sheet name + range name).
- The instructor's demo graph was called the "dynamic graph."

**The instructor said explicitly: this will not be on the exam. Just explore the concept.**

## 3. Exam / Assignment Flags

## 4. Quick Reference

| Tool | Path | Key settings |
|---|---|---|
| One-way data table | Data → What-If Analysis → Data Table | Column input cell = the varied input |
| Two-way data table | Data → What-If Analysis → Data Table | Row input = top-row variable; Column input = left-column variable |
| Goal Seek | Data → What-If Analysis → Goal Seek | Set cell (formula) → To value → By changing (one input) |
| Scenario Manager | Data → What-If Analysis → Scenario Manager | Add → changing cells → values; Summary → Summary or PivotTable report; choose result cells |
| Named ranges | Formulas → Create from Selection / Name Manager | Left column labels |

```excel
=-PMT(B2/12,B3*12,B1)        ' EMI (monthly, end of period)
=-PMT(B2/12,B3*12,B1,0,1)    ' EMI if paid at beginning of period
=B6*B3*12                    ' Total paid to bank
=B7-B1                       ' Extra paid
{=TABLE(,B3)}                ' one-way table, column input = tenure (auto-generated)
{=TABLE(B3,B2)}              ' two-way table, row = tenure, column = rate (auto-generated)
```

**Formulas:**

$$EMI = \frac{P\,r\,(1+r)^{n}}{(1+r)^{n}-1}$$

$$\text{Profit} = P \cdot Q - (FC + VC \cdot Q)$$

$$Q_{\text{break-even}} = \frac{FC}{P - VC}$$
